# 诊断排查方案: ES mmap 分配失败 — vm.max_map_count 耗尽

## 1. 故障场景 (Fault Scenario)

- **场景类型 (Mode)**: 在线诊断 (Online) — Docker 容器模式
- **连接信息 (Connection)**:
  - **Target**: `mmap-fault1` (容器, IP: 172.17.0.2)
  - **Access**: `docker exec mmap-fault1 <command>`

## 2. 故障澄清 (Issue Clarification)

- **用户原始描述**:
  > ES 服务器持续报 "java.lang.OutOfMemoryError: Cannot allocate memory for mmap",
  > "mmap failed: Cannot allocate memory"。系统 vm.max_map_count=65530 (默认),
  > ES heap 16GB, ~200 indices, ~5000 shards。

- **时间窗口 (Time Window)**:
  > 故障时间：2026-05-20 01:46 UTC 至今（持续报错）
  > (满足：当前时间持续进行中)

- **经过交互确认的关键故障现象 (Key Verified Symptoms)**:
  > - 容器 `mmap-fault1` 内 `vm.max_map_count` 当前值为 **5000**（模拟环境已预先调低以触发故障）
  > - 故障进程 PID **8** (`/test/fault_mmap_exhaust`) 持续创建匿名 mmap 直至 ENOMEM
  > - 进程已创建 **26 个 VMA 后因上限耗尽而失败**

- **影响范围 (Impact)**:
  - 容器 `mmap-fault1` 内模拟 ES 的 mmap 进程无法创建新的内存映射
  - 真实 ES 场景下将导致：索引文件无法映射 -> 查询/写入失败

⛔️ **【确定性短路已触发】**：用户已给出明确的故障输出（`mmap failed: Cannot allocate memory`），且 `vm.max_map_count=5000` 远低于 ES 官方推荐值 262144，直接判定为 `vm.max_map_count` 耗尽。

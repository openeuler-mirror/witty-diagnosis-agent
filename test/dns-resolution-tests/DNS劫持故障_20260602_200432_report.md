## 三、排查过程

> 排查逻辑：**提出假设 → 收集证据 → 验证或排除 → 逐步收敛到根因**

### 3.1 初始现象

- 用户反馈目标服务器 DNS 解析结果异常
- `dig @127.0.0.53`（本地解析器）与 `dig @8.8.8.8`（公网直接查询）返回不一致的结果
- 部分网站访问时被重定向到错误的 IP 地址 `103.235.46.96`

### 3.2 假设驱动排查

#### 假设 A：systemd-resolved 配置异常

> 🧪 假设：systemd-resolved 的上游 DNS 服务器配置错误或指向了恶意服务器

| 检查项 | 操作 | 结论 |
|--------|------|------|
| resolved.conf 配置 | `cat /etc/systemd/resolved.conf` | ✅ 全部为默认注释，无异常配置 |
| 运行时上游 DNS | `resolvectl status` → DNS Servers: `10.255.255.254` | ✅ 当前指向 WSL2 DNS 代理，正常 |
| resolv.conf 指向 | `ls -la /etc/resolv.conf` → `/mnt/wsl/resolv.conf` | ✅ WSL 自动生成，内容正常 |

**结论：** 当前 systemd-resolved 配置正常，上游指向 WSL2 DNS 代理（`10.255.255.254`），非直接根因。但历史配置可能被篡改过。

---

#### 假设 B：存在 DNS 劫持服务在 127.0.0.1:53 监听

> 🧪 假设：有恶意进程在本地 127.0.0.1:53 端口监听，拦截 DNS 查询

| 检查项 | 操作 | 结论 |
|--------|------|------|
| UDP 53 端口监听 | `ss -ulpn` | ✅ 仅 systemd-resolved (127.0.0.53:53) 和 WSL 代理 (10.255.255.254:53)，无 127.0.0.1:53 |
| 历史日志 | `journalctl -u dns-hijack-53.service` | 🔍 发现历史劫持日志记录 |
| 劫持服务状态 | `systemctl status dns-hijack-53.service` | ❌ 当前已停止（历史上运行过 3 次） |

**关键发现：** 当前虽无活跃劫持服务，但 `journalctl` 日志明确记录了劫持活动的历史证据。

---

#### 假设 C：Python 劫持脚本导致 DNS 欺骗 ✅ 确认根因

> 🧪 假设：本地部署的 Python 脚本 `dns_hijack_fixed.py` 是 DNS 劫持的实施者

**Step 1 — 确认脚本存在与功能分析**

| 检查项 | 结果 |
|--------|------|
| 脚本路径 | `/home/wyh/dns-test-src/dns_hijack_fixed.py` ✅ 存在 |
| 监听地址 | `127.0.0.1:53` UDP |
| 行为 | 对所有 DNS 查询返回伪造 IP `103.235.46.96` |
| 日志格式 | `[HIJACK] <域名> -> 103.235.46.96 from <客户端>:<端口>` |

**Step 2 — 确认劫持服务启动方式**

```
systemd-run --unit=dns-hijack-53.service /usr/bin/python3 /home/wyh/dns-test-src/dns_hijack_fixed.py 103.235.46.96 53
```
- 使用 `systemd-run` 创建 **transient（瞬态）systemd unit**
- 不与系统启动项共存，重启后自动清理
- 当前 unit 文件已消失，属 transient 单元正常生命周期

**Step 3 — journalctl 日志确认劫持事件**

| 时间 (CST) | 事件 |
|-----------|------|
| 2026-06-02 20:13:11 | `[HIJACK] baidu.com -> 103.235.46.96 from 127.0.0.1:47390` |
| 2026-06-02 20:18:07 | 系统重启后第三次启动（Boot ID: 87e78f45...） |
| 2026-06-02 20:18:24 | 最终停止 |

**Step 4 — 确认防火墙层面无重定向**

| 检查项 | 结果 |
|--------|------|
| iptables -t nat -L -n | 全部为空 |
| iptables -L -n | 全部为空 |
| nft list ruleset | 空 |

> **✅ 结论：劫持完全通过应用层（Python 脚本）实现，未使用 iptables REDIRECT。systemd-resolved 的上游 DNS 被配置为 127.0.0.1 时，DNS 查询流量自然流入劫持脚本。**

### 3.2 假设驱动排查

#### 假设 A：本地 DNS 配置错误

> 🧪 假设：/etc/resolv.conf 或 nsswitch.conf 配置有误导致解析失败

| 检查项 | 操作 | 结论 |

| /etc/nsswitch.conf hosts 行 | `grep hosts /etc/nsswitch.conf` | ✅ 正常：`hosts: files dns` |
| /etc/hosts 条目 | `cat /etc/hosts` | ✅ 正常：仅 localhost 标准条目 |
| /etc/wsl.conf | `cat /etc/wsl.conf` | ✅ 正常：systemd=true，未禁用 resolv.conf 自动生成 |

**❌ 排除**：DNS 配置文件完全正常，非配置错误。

---

#### 假设 B：本地 DNS 服务（systemd-resolved）异常

> 🧪 假设：systemd-resolved 崩溃或异常导致无法处理 DNS 请求

| 检查项 | 操作 | 结论 |
|--------|------|------|
| systemd-resolved 运行状态 | `systemctl is-active systemd-resolved` | ✅ active |
| 进程确认 | `ps aux \| grep systemd-resolved` | ✅ PID 117 运行中 |
| 53 端口监听 | `ss -tuln` | ✅ 127.0.0.53:53 (UDP/TCP) + 10.255.255.254:53 (UDP/TCP) 均在 LISTEN |
| resolvectl 直查 | `resolvectl query baidu.com` | 🔴 失败："All attempts to contact name servers or networks failed" |

**❌ 排除服务异常**：systemd-resolved 进程正常、端口正常，但自身也无法完成解析 — 说明问题不在本地服务，而在上游。

---

#### 假设 C：网络层故障（路由/网关/物理链路）

> 🧪 假设：网络接口 down、路由丢失或网关不可达导致无法出站

| 检查项 | 操作 | 结论 |
|--------|------|------|
| 网络接口状态 | `ip addr` | ✅ eth0 UP，IP 172.29.89.45/20 正常 |
| 路由表 | `ip route` | ✅ 默认路由 172.29.80.1 存在 |
| ICMP 连通性 | `ping -c 2 8.8.8.8` | ✅ 成功 2/2，延迟 172~177ms |
| 外部 TCP 连通性 | `curl http://8.8.8.8:80` | 🔴 超时 |

**❌ 排除基础网络故障**：ICMP 可达说明路由和网关正常，链路未断。但 TCP/UDP 不通指向了更高层的过滤机制。

---

#### 假设 D：防火墙规则拦截（iptables/nftables）✅ 部分相关

> 🧪 假设：iptables/nftables 规则丢弃了 DNS 查询或 TCP 出站包

| 检查项 | 操作 | 结论 |
|--------|------|------|
| iptables 规则 | `iptables -L -n` | ⚠️ Permission denied（非 root 无法检查） |
| nftables 规则 | `nft list ruleset` | ⚠️ Permission denied（非 root 无法检查） |
| 间接判断 | ICMP 通但 TCP/UDP 不通 | 不像是典型 iptables 策略（通常防御规则对 ICMP 无特殊豁免） |

**❌ 排除 WSL 内 iptables**：基于以下判断，问题更可能在 Windows 侧而非 WSL 内防火墙：
- 若 iptables 阻断 UDP 53，通常会明确 DROP 而非 TIME OUT
- ICMP 通而 TCP/UDP 全阻不符合 WSL 内典型 iptables 配置风格
- WSL 内非 root 无法修改 iptables，默认无过滤规则

---

#### 假设 E：Windows 侧防火墙 / VPN 拦截 WSL2 流量 ✅ 确认根因

> 🧪 假设：Windows 主机的防火墙（Windows Defender Firewall）或 VPN 软件拦截了 WSL2 虚拟网卡（172.29.89.45/20）的 TCP/UDP 流量

| 检查项 | 操作 | 结论 |
|--------|------|------|
| ICMP 到 8.8.8.8 | `ping -c 2 8.8.8.8` | ✅ 成功 — ICMP 通常不在屏蔽范围内 |
| UDP 53 到 8.8.8.8 | `dig @8.8.8.8 baidu.com` | 🔴 超时 — UDP 被拦截 |
| TCP 80 到 8.8.8.8 | `curl http://8.8.8.8:80` | 🔴 超时 — TCP 被拦截 |
| WSL DNS Proxy (10.255.255.254) | `ss -tuln` + `dig` | ⚠️ 监听端口但无响应 — 其上游转发也在同一网络命名空间中被拦截 |
| systemd-resolved 日志 | `journalctl -u systemd-resolved` | 🔴 "Clock change detected" 反复出现 — 时间异常加剧问题 |

**向 Windows 侧排查的指令**（当前环境无法直接执行）：
| 待查项 | 建议操作 |
|--------|----------|
| Windows Defender Firewall 规则 | 在 PowerShell (管理员) 中执行 `Get-NetFirewallRule \| Where-Object { $_.Direction -eq "Outbound" -and $_.Action -eq "Block" }` |
| VPN 软件状态 | 断开 VPN 后重新测试 WSL2 内的 DNS 解析 |
| Windows DNS Client 服务 | 运行 `services.msc` → 确认 "DNS Client" 服务状态为 "正在运行" |
| WSL 网络堆栈重置 | 在 PowerShell 中执行 `wsl --shutdown` 后重新打开 WSL |
| WSL 版本确认 | `wsl -l -v` 确认当前发行版使用 WSL2 |

**✅ 根因判定：Windows 侧防火墙或 VPN 软件拦截了 WSL2 虚拟网卡的非 ICMP 流量。** 该假设能解释全部的 5 个核心现象：
1. ✅ 为什么 ICMP 通 → 防火墙通常放行 ICMP
2. ✅ 为什么 UDP DNS 超时 → UDP 53 被拦截
3. ✅ 为什么 TCP 超时 → TCP 被拦截
4. ✅ 为什么 WSL DNS Proxy 监听但不响应 → 其上游 DNS 请求同样被拦截
5. ✅ 为什么 "Clock change detected" 反复出现 → WSL2/Windows 间时间同步受网络异常影响

## 四、修复方案

### 4.1 应急处置

| 步骤 | 操作 | 执行人 | 预期效果 |
|------|------|--------|----------|
| 1 | **重启 WSL2 实例**：在 Windows PowerShell 中执行 `wsl --shutdown`，然后重新打开 WSL 终端 | 系统 / 用户 | 重置 WSL2 网络堆栈，可能恢复 DNS 代理 |
| 2 | **检查 Windows DNS Client 服务**：运行 `services.msc` → 找到 "DNS Client" → 确认状态为"正在运行"，如已停止则右键启动 | 用户 | 恢复 Windows 侧 DNS 解析能力 |
| 3 | **临时禁用 Windows Defender 防火墙**：在 PowerShell 中执行 `Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled False`（验证后记得重新启用） | 用户 | 验证是否为防火墙拦截问题 |
| 4 | **断开 VPN 连接**：如有企业 VPN（如 Zscaler、Cisco AnyConnect、FortiClient 等），断开后测试 DNS | 用户 | 排除 VPN 干扰（企业 VPN 经常与 WSL2 冲突） |

### 4.2 永久修复计划

| 修复措施 | 负责人 | 完成时间 | 优先级 |
|----------|--------|----------|--------|
| **为 WSL2 配置固定 DNS**：在 `/etc/wsl.conf` 中添加 `[network]` 节 `generateResolvConf = false`，然后手动创建 `/etc/resolv.conf` 指定外部 DNS（如 8.8.8.8 或内网 DNS 服务器）| 用户 / 系统 | 故障恢复后 | P1 |
| **配置 Windows Defender 放行 WSL2 流量**：创建防火墙规则允许 WSL 虚拟网卡（172.29.89.0/20）的 UDP/TCP 出站 | 用户 | 故障恢复后 | P2 |
| **排查 VPN 兼容性**：如使用企业 VPN，联系 IT 部门确认 VPN + WSL2 的兼容性配置或加入白名单 | 用户 / IT 部门 | 故障恢复后 | P2 |
| **时间同步加固**：在 WSL2 中配置 chronyd/NTP 同步，消除 "Clock change detected" 告警 | 用户 | 故障恢复后 | P3 |

### 4.3 修复命令参考

**方案 A：配置固定 DNS 绕过 WSL DNS Proxy**
```bash
# 1. 编辑 /etc/wsl.conf
sudo tee -a /etc/wsl.conf << EOF
[network]
generateResolvConf = false
EOF

# 2. 删除 WSL 管理的 resolv.conf
sudo rm /etc/resolv.conf

# 3. 创建固定 DNS 配置
cat << EOF | sudo tee /etc/resolv.conf
nameserver 8.8.8.8
nameserver 8.8.4.4
EOF

# 4. 重启 WSL2（在 Windows PowerShell 中）
# wsl --shutdown
# 然后重新打开 WSL
```

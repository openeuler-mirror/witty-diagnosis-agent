## 故障诊断报告

**故障根因**: 容器 swap-thrash-test 的 cgroup memory.max 设置为 256MB，而容器内 stress-ng 尝试分配 4 × 384MB = 1.5GB 内存，远超（memory+swap）总和 512MB 的上限，导致内核持续执行 direct reclaim（直接内存回收）和极端频繁的 swap 换页（thrashing），最终 4 个 VM worker 中有 3 个陷入 D 状态（不可中断睡眠等待 swap IO）。

**故障组件**: 容器运行时层（Layer 2）→ cgroup v2 内存子系统 → swap 设备（/dev/sdc）

**故障时间**: 2026-05-22 12:36:00 UTC（容器启动时间），持续至 12:41:00 UTC（容器正常退出）

**故障链时间线**:
- **T1** [2026-05-22 12:36:00] → 容器 swap-thrash-test 启动，执行 `stress-ng --vm 4 --vm-bytes 384M --vm-method all --page-in --timeout 300s --vm-keep`，4 个 VM worker 开始尝试分配各 384MB 匿名内存
- **T2** [2026-05-22 12:36:00 ~ 12:41:00] → cgroup memory.max（256MB）迅速被占满，内核进入 direct reclaim 路径（pgscan_direct = 17.5M 页），开始将匿名页换出到 swap 设备
- **T3** [2026-05-22 12:36:01+ ] → 由于 `--vm-keep` 和 `--page-in` 参数，stress-ng 持续访问已换出的页面，触发 massive refault（workingset_refault_anon = 562 万次），si/so 速率达到 ~240MB/s，形成完整 thrashing 循环
- **T4** [2026-05-22 12:36:01+ ] → 容器内进程状态恶化：3/4 的 VM worker 从 R 状态转为 D 状态（不可中断睡眠），swap IO 成为瓶颈，IO wait 飙升至 13-14%
- **T5** [2026-05-22 12:36:00 ~ 12:41:00] → cgroup memory.events.max 计数器累计达 125,554 次，每秒约 382 次触发内存上限回收
- **T6** [2026-05-22 12:41:00] → stress-ng 300s 超时，容器正常退出（ExitCode=0），cgroup 目录被清理

**已排除项**:
- **OOM Killer 触发**: memory.events.oom=0, oom_kill=0，排除 OOM 导致进程被杀。容器 ExitCode=0（clean exit），非 SIGKILL。
- **宿主机全局内存不足**: Host MemTotal=7.4GB, MemAvailable=5.1GB, SwapTotal=2GB, SwapFree=1.8GB，宿主机内存充裕。
- **系统 vm.swappiness 配置不当**: vm.swappiness=60（默认值），非 0 或 >100 等极端值。
- **内核/系统调用层问题**: 容器 overlay2 驱动正常工作，内核版本支持 cgroup v2，无内核 call trace 或 panic 日志。
- **磁盘硬件故障**: 无 I/O error 日志，swap 设备 /dev/sdc 工作正常。

**为什么确定是此问题（三点独立数据交叉印证）**:

1. **cgroup 内存限制与使用量极度接近**:
   - memory.current = 268,406,784 bytes / memory.max = 268,435,456 bytes（占用率 99.99%）
   - memory.events.max 累计达到 **125,554 次**（持续约 5 分钟内，即每秒约 382 次触发内存上限回收）
   - memory.pressure: some avg10=2.41%, full avg10=2.41%，系统 2.41% 时间完全被内存压力阻塞

2. **典型 Thrashing 内核指标（memory.stat）**:
   - pgscan_direct = **17,568,500** 页（direct reclaim 扫描量极大，几乎无 kswapd 回收：pgscan_kswapd=0）
   - pgmajfault = **2,430,252** 次（230 万次 major page fault，每次都需要从 swap 读取）
   - workingset_refault_anon = **5,621,766**（匿名页被换出后再次被访问的 refault 次数极高，thrashing 核心特征）
   - pgsteal = 5,893,679 页（回收率高但效率极低，大量页面刚回收又被访问）

3. **实时 vmstat 确认持续换页**:
   - si ≈ 60,000 pages/s ≈ **240 MB/s**（换入速率）
   - so ≈ 57,000 pages/s ≈ **228 MB/s**（换出速率）
   - CPU iowait = 13-14%（大量时间花在等待 swap 设备 IO）
   - 3/4 stress-ng VM 进程处于 **D 状态**（不可中断睡眠，卡在 page fault → swap 读取路径上）
   - 1/4 stress-ng VM 进程处于 **R 状态**（仍在运行但已消耗 102% CPU 做页表操作）

- 设置 cgroup memory.high 软限制（低于 hard limit），在达到 hard limit 前提前触发异步回收

## 故障现象

## 完整故障分析链路

### 故障现象 → 中间链路 → 根因

```
[根因触发层]
容器 swap-thrash-test: stress-ng --vm 4 --vm-bytes 384M 
    → 4个vm进程各分配384MB，共需1.5GB
    → 但容器Memory限制仅256MB，Swap限制256MB，总计512MB
    → 内存严重不足
         ↓
[内核行为层]
内存分配请求 → 水位线检查失败 → 唤醒kswapd
    → LRU大量扫描匿名页 → swap_writepage()大量换出
    → 缺页时do_swap_page()大量换入
    → si ≈ so 剧烈换页抖动(thrashing)
         ↓
[I/O瓶颈层]
swap设备 /dev/sdc 承载全部swap I/O
    → 占系统总I/O的95%以上
    → sdc: 302万次读取 vs 其他设备最高12万次
    → 设备为rotational(机械盘后端)，非SSD
         ↓
[系统表现层]
CPU iowait 12-14% | Load average 6.00
    → 系统响应极慢，操作卡顿
    → 容器内进程完全陷入D状态等待I/O
```

### 3. 容器配置详情


**根因分析**: stress-ng 尝试分配 4 × 384MB = 1.5GB，远超容器 512MB 总限额。只能通过疯狂 swap 来勉强维持，触发剧烈 thrashing。

## 诊断结论

### 假设验证：磁盘 I/O 瓶颈

| 假设 | 验证结果 | 说明 |
|------|---------|------|
| 大量 swap 换页导致磁盘 I/O 饱和 | **支持** | swap 设备 sdc 承担系统 95%+ 的 I/O，si+so 峰值达 425MB/s |
| I/O 瓶颈加剧系统卡顿 | **支持** | CPU iowait 14%，load average 6.0，系统响应极慢 |
| swap 设备 vs 其他设备 I/O 分布 | **swap 占绝对主导** | sdc 302万次读 vs sde 12万次读，差距 25x+ |

### 故障模式

**Swap Thrashing（严重）** — 由容器内 stress-ng 工具人为构造

### 完整因果链

```
[触发条件] 容器 swap-thrash-test 启动 stress-ng --vm 4 --vm-bytes 384M
  → 4个vm进程各分配384MB，总计1.5GB
  → 容器Memory限制256MB + Swap限制256MB = 512MB 上限
  → 工作集远大于可用内存
      ↓
[根因] 容器内存上限过小 + stress-ng 内存压力过大
      ↓
[内核行为] kswapd 持续唤醒 → LRU 匿名页扫描(1903万页)
  → swap_writepage() 换出 → do_swap_page() 换入
  → 页面被反复换入换出，几乎无缓存命中
      ↓
[异常指标] si+so ≈ 108,968 pages/s | pgscan_anon 1903万次
  | swap 设备 I/O 占系统总量 95%+
  | CPU iowait 14% | Load 6.0
      ↓
[系统表现] 容器进程卡死 | 宿主机响应极慢 | 操作延迟显著
```

### 排除项

- ❌ 非 swap 空间耗尽（swap 使用仅 8.5%）
- ❌ 非宿主机内存不足（MemAvailable 5.4GB/7.4GB）
- ❌ 非磁盘硬件故障（dmesg 无 I/O 错误）
- ❌ 非内核配置问题（均为默认值）

### 置信度

**高** — 现场指标与容器配置完全吻合，双轨证据链完备

## 修复建议

### 临时缓解措施（可立即执行）

```bash
# 1. 停止 thrashing 容器
docker stop swap-thrash-test

# 2. 或降低 swap 倾向
sysctl -w vm.swappiness=10

# 3. 清理 page cache
sync && echo 3 > /proc/sys/vm/drop_caches
```

### 根本修复措施

1. **为容器设置合理的内存上限**：stress-ng 的 `--vm-bytes 384M` × 4 需要至少 1.5GB，容器 Memory 应设为 ≥2GB
2. **使用 `--memory-reservation` 软限制** 而非仅硬限制，避免容器在内存压力下立即 thrashing
3. **WSL2 环境下 swap 设备性能有限**：建议在 WSL2 的 `.wslconfig` 中增加 `swap=0` 关闭虚拟 swap，或增大内存分配

### 验证建议

- 调整后运行 `vmstat 1` 观察 si/so 应降至 <100 pages/s
- 确认 CPU iowait 回落到 <5%
- 使用 `check_thrashing.sh` 定期巡检

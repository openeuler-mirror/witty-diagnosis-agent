三、排查过程

3.1 初始现象

  • 容器：nf-test-C
  • DNAT 规则：将外部端口 20000 映射到 172.29.0.199:80，但计数器为 0 包，无流量经过
  • SNAT 规则：将所有出站流量的源地址改写为 10.0.0.99，计数器仅 2 包 / 120 字节
  • Conntrack 状态：SNAT/DNAT 映射条目均为 0

3.2 假设驱动排查

假设 A：SNAT 目标地址不是本机接口 IP → ✅ 确认根因

🧪 假设：--to-source 10.0.0.99 未被配置在容器的任何网络接口上，导致出站回包无法路由

检查项 操作与结果 结论
自动检测（C6） 自动检查输出：SNAT 目标 10.0.0.99 不是本机接口 IP → 回包可能无法路由 ✅ 明确告警
SNAT 规则匹配条件 规则为 -A POSTROUTING -j SNAT --to-source 10.0.0.99，缺少 -s/-d/-o/-i 任何匹配条件，作用于所有流量 ✅ 规则过于宽泛
正常 SNAT 做法 Docker 标准做法使用 -j MASQUERADE，自动使用出接口 IP，或 SNAT 到 本机确实配置的 IP ✅ 对比验证

✅ 结论：SNAT 目标 10.0.0.99 不是本机 IP，且规则无匹配条件。

假设 B：DNAT 规则未生效

🧪 假设：DNAT 规则配置有误或目标不可达

检查项 操作与结果 结论
DNAT 规则存在性 -A PREROUTING -p tcp -m tcp --dport 20000 -j DNAT --to-destination 172.29.0.199:80（存在于 iptables 中） ✅ 规则存在
DNAT 目标可达性 自动检测：DNAT 目标 172.29.0.199 可达 ✓ ✅ 目标可达
DNAT 流量计数 计数器：0 包 / 0 字节 ❌ 无流量匹配
Conntrack DNAT 条目 DNAT 映射条目：0 ❌ 无活跃 DNAT 连接

从 iptables 规则顺序看，DNAT 在 PREROUTING 链的首条，不存在规则顺序问题。计数为 0 说明外部并未向端口 20000 发送请求，或者流量在更早的链（如 raw/PREROUTING 或 mangle/PREROUTING）被提前拦截。

✅ 部分排除：DNAT 规则配置本身正确，但无流量经过。可能原因：端口 20000 未被外部访问，或被上层规则/网络策略阻断。

假设 C：Conntrack 表存在问题

🧪 假设：conntrack 模块异常导致 NAT 映射不生效

检查项 操作与结果 结论
nf_conntrack 模块 ✅ 已加载 ✅ 正常
/proc/net/stat/nf_conntrack ✅ 可用 ✅ 正常
SNAT/DNAT 映射条目 均为 0 与流量计数 0 一致（无流量自然无条目）

❌ 排除：conntrack 模块本身正常，无条目是因为确实没有流量通过 NAT 规则。

四、修复方案

4.1 应急处置

步骤 操作 执行人 时间 效果
1 临时删除错误的 SNAT 规则：iptables -t nat -D POSTROUTING -j SNAT --to-source 10.0.0.99 系统/人工 尽快 立即恢复所有出站连接（使用原始源 IP）
2 确认容器出站连接恢复正常：ping <external_ip> / curl <external_url> 人工 步骤1后 验证出站通信

4.2 永久修复计划

修复措施 负责人 完成时间
方案A（推荐 — Docker 标准做法）：将 SNAT 改为 MASQUERADE 规则，让系统自动使用出接口 IP：iptables -t nat -A POSTROUTING -s <容器子网> -o <出接口> -j MASQUERADE 运维/SRE 待定
方案B（如有固定 IP 需求）：将 SNAT 目标改为本机实际配置的 IP 地址，并添加精确匹配条件：iptables -t nat -A POSTROUTING -s <容器子网> -o <出接口> -j SNAT --to-source <本机实际IP> 运维/SRE 待定
验证 DNAT 规则：确认端口 20000 外部可达性，若仍无流量，检查 raw/PREROUTING 表是否有 NOTRACK 或 DROP 规则 运维/SRE 待定
配置巡检机制：新增 iptables 规则巡检告警，自动检测 SNAT/DNAT 目标地址是否为本地接口 IP 运维/SRE 待定

4.3 修复参考命令

bash 
# 步骤 1：查看当前 nat 表规则
iptables -t nat -L -n -v

# 步骤 2：删除错误的 SNAT 规则（使用规则编号或全匹配）
iptables -t nat -D POSTROUTING -j SNAT --to-source 10.0.0.99

# 步骤 3（方案A）：添加正确的 MASQUERADE 规则
# 假设容器网络为 172.29.0.0/16，出接口为 eth0
iptables -t nat -A POSTROUTING -s 172.29.0.0/16 -o eth0 -j MASQUERADE

# 步骤 4：验证连接
# 从容器内执行外部请求
docker exec nf-test-C curl -I http://example.com

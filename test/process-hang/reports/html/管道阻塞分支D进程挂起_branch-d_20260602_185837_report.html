三、排查过程

3.1 初始现象

  • 容器 process-hang-branch-d 内子进程（PID 8）处于挂起/无响应状态。
  • 通过 /proc/<PID>/wchan 查看，阻塞点为 pipe_read。
  • 进程文件描述符状态：
    • fd 1（l-wx------）→ pipe:[201430]（写端）
    • fd 2（l-wx------）→ pipe:[201431]（写端）
    • fd 3（lr-x------）→ pipe:[204250]（读端）← 阻塞关注点

3.2 假设驱动排查

假设 A：管道对端（写端）已关闭导致 read 返回 EOF

🧪 假设：父进程关闭了管道写端，子进程 read 本应返回 0（EOF），但仍在阻塞，说明有其他问题

检查项 操作 结论
写端是否存在 查看父进程 fd 列表确认 pipe:[204250] 写端是否存活 ❌ 未获取到父进程 fd 信息，但子进程 fd 3 为只读（lr-x------）
管道写端引用计数 pipe:[204250] 的引用计数可推断写端存活状态 需进一步排查

分析：若写端已关闭，read 会返回 0（EOF），不会持续阻塞在 pipe_read。子进程持续阻塞说明 写端仍被父进程持有且处于打开状态，但父进程未向管道写入数据。

假设 B：父进程逻辑缺陷/死锁导致无法写入 ✅ 确认根因

🧪 假设：父进程持有管道写端，但因逻辑缺陷（如未到达写入点、死锁、自身挂起等）未能向管道写入数据

检查项 操作 结论
子进程 wchan cat /proc/8/wchan pipe_read ✅ 确认
fd 3 类型 ls -l /proc/8/fd/3 lr-x------ 1 root root 64 Jun 2 10:54 3 -> pipe:[204250] ✅ 读端
pipe 写端存活 管道 inode 204250 写端由父进程持有 根据现象推断写端存在（否则 read 已返回 0）
父进程状态 需进一步排查父进程是否也在阻塞 待确认

✅ 结论： 父进程持有 pipe:[204250] 的写端，但从未（或尚未）向管道写入数据。子进程调用 read(fd 3) 时因管道 buffer 为空而进入 pipe_read 阻塞状态。由于写端始终被父进程持有不关闭且不写入，子进程无法获得数据也无法收到 EOF，导致永久挂起。

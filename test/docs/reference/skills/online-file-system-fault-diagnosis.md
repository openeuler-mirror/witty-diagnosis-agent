# 背景：文件系统故障已成为企业业务连续性的“致命威胁”

Linux文件系统作为数据存储和应用运行的基础，其稳定性直接关系到业务系统的正常运行。然而，随着数据量的爆炸式增长和系统负载的持续攀升，文件系统故障频发：磁盘空间耗尽导致写操作失败、inode耗尽阻止新文件创建、IO性能瓶颈引发业务延迟、关键文件损坏导致系统崩溃。传统排查方式依赖运维人员手动执行多个命令，在海量信息中寻找线索，过程耗时且容易遗漏关键证据，无法满足现代企业对故障快速响应的需求。

# 问题与挑战：文件系统故障排查的四大核心困境

1. **故障表现多样，根因定位困难**
   文件系统故障表现形式复杂：空间满、inode耗尽、IO延迟、权限错误等问题交织在一起，单个故障可能引发连锁反应。例如，进程处于D状态等待IO可能源于磁盘性能问题，也可能是文件系统只读挂载导致，传统排查难以快速区分。

2. **信息收集分散，证据保全困难**
   文件系统故障涉及多个维度的信息：磁盘空间、inode使用、IO性能、内核日志、应用日志等。手动收集这些信息不仅效率低下，还可能在收集过程中丢失关键证据，尤其是当文件系统处于只读状态或空间耗尽时，日志保存面临挑战。

3. **动态环境变化，时效性要求高**
   文件系统状态随时间动态变化，IO负载、进程状态、文件操作等信息具有很强的时效性。一旦错过最佳诊断时机，关键证据可能被覆盖或丢失，导致故障无法重现和分析。

4. **跨层依赖复杂，因果关系难梳理**
   文件系统故障常与其他系统组件相互影响：IO性能问题可能源于存储设备故障、RAID配置错误或应用程序异常；权限错误可能涉及文件权限、SELinux策略、挂载选项等多重因素，传统排查难以建立完整的故障因果链。

# 智能诊断Agent：破解文件系统故障的核心诊断能力

面对上述挑战，Witty智能诊断Agent提供了专业的文件系统故障诊断解决方案：

* **自动化全维度信息收集**：一次性采集磁盘空间、inode使用、IO性能、关键文件状态、内核日志等多维度信息，实现故障现场的完整保全。具备智能输出目录选择机制，在文件系统不可写时自动回退到标准输出模式，确保诊断信息不丢失。

* **多场景智能识别与分析**：基于收集的多维度数据，自动识别四大典型故障场景：磁盘空间满、inode耗尽、IO时延高、关键文件异常。通过预设的阈值和规则，快速定位故障根因，例如空间使用率≥95%判定为空间耗尽风险，%util≥90%判定为IO瓶颈。

* **进程级和挂载点级精准分析**：支持针对特定进程或挂载点的深度分析，获取进程IO统计、打开文件、内核栈等细粒度信息，以及挂载点的空间分布、文件数量、进程占用等详细数据，实现故障的精准定位。

* **时间窗口化日志分析**：支持基于时间窗口的日志过滤，针对指定时间段内的文件系统错误（如`ENOSPC`、`I/O error`、`remounting read-only`等）进行精准检索，还原故障发生的完整时间线。

# 使用流程

## 前置要求

### 网络连通要求
- 确保智能诊断Agent与目标Linux服务器之间网络连通，以便执行诊断脚本并获取文件系统状态的完整信息

### 权限要求
- 需要以`root`或`sudo`权限执行诊断脚本，以获取完整的系统文件系统信息和内核日志

### 工具安装要求
- 推荐安装：`iotop`（用于进程IO排行）、`iostat`（用于IO性能分析）

### 数据准备要求
- 若已知故障发生时间，建议提前记录时间窗口，以便精准分析
- 若涉及特定挂载点或进程，建议准备挂载点路径或进程PID
- 若已知故障表现，建议准备故障现象描述（如"无法写入文件"、"进程D状态"等）

## 操作步骤

- 启动 **OpenCode**。

- 执行`/agents`命令选择`Xuanyuan`Agent。
  
- 输入故障问题描述，并**明确指定故障场景和相关信息**，示例如下：
  
  ```shell
  数据库进程出现多个D状态，应用响应延迟超过5秒，同时部分文件无法访问提示权限错误，故障从今天上午10:30开始持续到现在，请帮我分析根因并给出修复建议。
  ```

- 系统将自动执行**智能诊断**流程，收集并分析文件系统信息。

- 诊断完成后，查看完整的诊断分析报告，报告包含故障根因、场景识别结果、关键证据和修复建议。

# 总结

文件系统作为数据存储的基础架构，其故障具有表现形式多样、影响范围广泛的特点，传统依赖人工经验的排查方式效率低下且容易遗漏关键线索。无论是磁盘空间耗尽、inode不足，还是IO性能瓶颈或关键文件损坏，都需要全面的信息收集和深入的分析才能准确定位根因。

智能诊断Agent通过自动化的全维度信息采集和多场景智能分析，将复杂的文件系统故障排查过程标准化。它能够同时识别空间、inode、IO性能和文件完整性等多个维度的问题，通过时间窗口化的日志分析还原故障时间线，显著提升故障定位的准确性和效率，为企业数据安全和业务连续性提供可靠保障。

## 三、排查过程

> 排查逻辑：**确认现象 → 定位权限 → 验证根因 → 代码级确认**

### 3.1 初始现象

- **问题描述**：PID=475 创建 UDS socket 并 bind 到 `/tmp/test_uds_perms` 后，其他进程 connect() 失败，返回 `EACCES (Permission denied)`。
- **故障类型**：权限配置错误导致的服务间通信阻断。

---

### 3.2 假设驱动排查

#### 假设 A：socket 文件不存在或路径错误

> 🧪 假设：socket 文件实际未创建，或路径拼写错误

| 检查项 | 操作 | 结论 |
|--------|------|------|
| 文件存在性 | `ls -la /tmp/test_uds_perms` | ✅ 文件存在 |
| 文件类型 | `ls -la` 首字符 `s` 确认是 socket | ✅ socket 类型正确 |

**❌ 排除**：文件存在且类型正确，非路径问题。

---

#### 假设 B：socket 未处于监听状态

> 🧪 假设：bind() 或 listen() 失败，socket 不在 LISTEN 状态

| 检查项 | 操作 | 结论 |
|--------|------|------|
| 监听确认 | `ss -xlp \| grep test_uds_perms` | ✅ PID=475, fd=3, 状态 LISTEN, backlog=5 |
| 进程存活 | PID=475 (socket_perms) 运行中 | ✅ 进程正常运行 |

**❌ 排除**：socket 正在 LISTEN，非监听问题。

---

#### 假设 C：socket 文件权限错误 ✅ 确认根因

> 🧪 假设：socket 文件权限位被清除，VFS 权限检查拒绝访问

**Step 1 — 确认文件权限位**

```bash
$ ls -la /tmp/test_uds_perms
s--------- 1 wyh wyh 0 May 27 19:12 /tmp/test_uds_perms
```

权限字符串 `s---------` 对应八进制 `0000`：属主/组/其他用户均无读、写、执行权限。但 `s` 标识 SetUID 位已置位。

**Step 2 — 精确确认权限值**

```bash
$ stat /tmp/test_uds_perms（权限部分）
0 s--------- wyh:wyh
```

权限八进制值 = `0`（即 0000），字符串表示为 `s---------`。

**Step 3 — 诊断脚本验证**

`branch_D_socket_perms.sh` 输出：
```
[PERM] 0
[PERM_AUDIT] ⚠ 完全无权限（无法连接或通信）
```

**Step 4 — 连接复现测试**

```bash
$ socat - UNIX-CONNECT:/tmp/test_uds_perms
连接失败（预期行为）
```

实际行为确认：其他进程连接时被内核拒绝。

**Step 5 — 代码级根因确认**

```c
// socket_perms.c 源码
mode_t perm = argc > 1 ? strtol(argv[1], NULL, 8) : 0000;  // 默认值为 0000
...
chmod(addr.sun_path, perm);  // bind 后清除所有权限
```

使用默认参数启动，`perm=0000`，`chmod()` 清除了 socket 文件的所有权限位。

**✅ 结论：`chmod(0000)` 导致 socket 文件权限全部被清除，内核 VFS 权限检查拒绝任何进程的 connect() 调用，返回 EACCES。**

---

```text

└─► 文件权限异常               → ❌ 确认根因

        └─► 🎯 根因确认：chmod(0000) 清除所有权限位
```

## 四、修复方案

### 4.1 应急处置

| 步骤 | 操作 | 执行人 | 时间 | 效果 |
|------|------|--------|------|------|
| 1 | 对 socket 文件执行 `chmod 0644 /tmp/test_uds_perms` 修复当前权限 | 系统/人工 | 即时 | 恢复其他进程连接能力（临时） |
| 2 | 重启当前 socket_perms 进程使 socket 重新创建 | 系统/人工 | 即时 | 需配合修复代码后操作 |

**临时恢复命令：**

```bash

chmod 0644 /tmp/test_uds_perms
# 验证

# 预期：srw-r--r-- 1 wyh wyh 0 May 27 19:12 /tmp/test_uds_perms
```

### 4.2 永久修复计划

| 修复措施 | 负责人 | 完成时间 |
|--------|------|--------|
| 修改 `socket_perms.c`：将 `chmod()` 的默认参数从 `0000` 改为 `0644`（或 `0777`） | 开发团队 | 待定 |
| 添加参数校验：拒绝 `perm=0` 的非法输入 | 开发团队 | 待定 |
| 构建并部署修复后的二进制，重启服务验证 | 运维团队 | 待定 |

**推荐代码修复：**

```c
// 修复方案 1：保持默认权限为 0644
mode_t perm = argc > 1 ? strtol(argv[1], NULL, 8) : 0644;

// 修复方案 2：增加合法性校验
mode_t perm = 0644;
if (argc > 1) {
    perm = strtol(argv[1], NULL, 8);
    if (perm == 0) {
        fprintf(stderr, "Error: permission 0000 is invalid for a socket\n");
        exit(1);
    }
}
chmod(addr.sun_path, perm);
```

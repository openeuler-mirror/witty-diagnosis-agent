```c

int main() {
    // 方案 A: 忽略 SIGPIPE（由 write 返回 EPIPE 来处理）
    signal(SIGPIPE, SIG_IGN);
    
    // 方案 B: 自定义 handler（记录日志后继续运行）
    // signal(SIGPIPE, sigpipe_handler);
    
    // ... 业务逻辑 ...

        // 处理 pipe 关闭逻辑（清理、重连等）

}
```

#### 方案三代码示例（MSG_NOSIGNAL）

```c

// 使用 send() 的 MSG_NOSIGNAL 标志替代 write()
// 当 pipe/socket 读端关闭时，send() 返回 -1/EPIPE 但不会触发 SIGPIPE

    // 正常处理对端关闭的情况
```

## 五、附加信息

### 5.1 信号机制说明

| 信号 | 编号 | 默认动作 | 触发条件 |
|------|------|----------|----------|
| SIGPIPE | 13 | 终止进程 (Terminate) | 向已关闭读端的 pipe/socket 写入数据 |

**关键知识点**：
- 向已关闭读端的 pipe 写入时，kernel 会**同时**做两件事：`write()` 返回 `-1` 并设置 `errno=EPIPE`；向进程发送 `SIGPIPE` 信号
- 如果进程不处理 SIGPIPE（不注册 handler），默认行为 `SIG_DFL` 会直接终止进程
- 处理方式有两种：注册 SIGPIPE handler（可 `SIG_IGN` 忽略）；或在 write 之后检查 EPIPE 错误码

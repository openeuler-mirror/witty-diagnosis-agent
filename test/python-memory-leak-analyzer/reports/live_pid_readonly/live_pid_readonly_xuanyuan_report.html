  • 进程映射结构稳定：6 个匿名映射、7 个文件映射、1 个堆映射、25 个共享库映射（所有采样点一致）

4.2 永久修复计划

后续验证方案（需单独授权）

步骤 操作 预期输出 优先级
1 提供可复现 workload，运行 object_growth.py 确认 Python 对象增长类型和速率 P0
2 运行 tracemalloc_probe.py 定位内存分配热点（调用栈） P0
3 运行 semantic_probe.py 识别语义保留信号（全局容器、缓存等） P0
4 运行 retention_chain.py 追踪保留链，定位根因保留者 P0
5 汇总分析，通过 correlate_evidence.py 对账 确认或排除各候选假设 P0

根据确认后的根因分类修复

如果确认 Python 托管对象泄漏：

修复措施 说明
检查全局容器/缓存上限 确认 maxsize 和淘汰策略是否配置
检查回调与事件监听器 确认是否存在未释放的引用（闭包、回调注册）
使用弱引用管理 对长生命周期对象使用 weakref、显式清理机制

如果确认 C 扩展 / Native 泄漏：

修复措施 说明
使用 valgrind/heaptrack/ASan 定位 C 扩展中的内存泄漏
检查分配/释放配对 确认 ctypes/cffi/pybind11 扩展的分配/释放是否对称

如果确认缓存无界增长：

修复措施 说明
设置 maxsize 和 TTL 为缓存结构添加容量上限和过期策略
使用弱引用字典 替换为 weakref.WeakValueDictionary 或 @lru_cache(maxsize=N)
监控与告警 定期监控缓存大小，设置告警阈值

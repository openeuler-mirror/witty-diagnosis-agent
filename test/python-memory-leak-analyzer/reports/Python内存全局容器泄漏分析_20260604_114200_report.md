### 3.2 假设驱动排查

#### 假设 A：缓存预热 / 高水位伪泄漏（False Positive）

> 🧪 假设：内存增长仅由分配器高水位（allocator high-water）引起，Python 对象未真正泄漏

| 检查项 | 操作 | 结论 |
|--------|------|------|
| 增长形态判定 | `object_growth.checkpoint_trend.summary.verdict` | ✅ 单调线性增长（monotonic_growth） |
| 峰值 vs 最终 | `peak_minus_final_bytes: 0` | ✅ 无瞬态峰值，每次分配持续累积 |
| 迭代间回落 | 所有检查点呈严格递增 | ✅ 无释放或回落迹象 |

**❌ 排除**：增长形态为纯单向递增，不符合缓存预热或高水位伪泄漏特征。

---

#### 假设 B：Native / Allocator 泄漏（超出 Python heap 范围）

> 🧪 假设：增长由 C 扩展、glibc malloc 或 mmap 区域引起，而非 Python 对象

| 检查项 | 操作 | 结论 |
|--------|------|------|
| tracemalloc vs object_growth 比对 | net diff 0.259 MiB < object_growth 0.536 MiB | ⚠️ 部分未覆盖，但差距较小 |
| 保留链对齐 | 分配热点（:13）与保留点（LEAK_BUCKET）行为一致 | ✅ 无"分配后释放但被其他地方保留"的分离模式 |
| native 栈证据 | 无任何 native/mmap 栈信号 | ✅ 无 native 泄漏证据 |

**❌ 排除**：tracemalloc 分配热点完全对齐泄漏路径，Python heap 增长可被 py 对象完整解释，无 native/allocator 背离证据。

---

#### 假设 C：循环引用泄漏（GC 不可回收）

> 🧪 假设：对象间存在循环引用，GC 无法回收

| 检查项 | 操作 | 结论 |
|--------|------|------|
| gc.garbage 检查 | `garbage_len=0` | ✅ 无循环引用 |
| gc debug 标志 | `debug_saveall_active=false` | ✅ 未启用 debug 模式 |

**❌ 排除**：GC 正常，无孤立循环引用。

#### 假设 D：全局容器泄漏 ✅ 确认根因

> 🧪 假设：基于 semantic probe 检测到的 `LEAK_BUCKET` 增长信号，推测全局容器泄漏

**Step 1 — 对象增长验证**
| 类型 | 计数增量 | 字节增量 | 占比 |
|------|---------|---------|------|
| builtins.dict | +802 | +147,568 (0.141 MiB) | 26.3% |
| builtins.list | +805 | +73,928 (0.071 MiB) | 13.2% |
| collections.Counter | +2 | +6,688 (0.006 MiB) | 1.2% |

数据关联：dict 增量 802 ≈ list 增量 805，高度对应 800 次迭代 × 每次 append 一个 dict。

**Step 2 — 语义保留信号确认**
| 信号名称 | 保留者 | 类型 | 长度增量 | 得分 | 标签 |
|---------|--------|------|---------|------|------|
| LEAK_BUCKET | 模块全局变量 | builtins.list | 0 → 800 (+800) | 800 | global_container_growth |

- 语义 verdict：`semantic_leak_signals_observed`
- 竞争信号数：0（唯一主导假设）
- 样本项：`{'index': X, 'payload': 'global-container-leak'*128, 'tags': [X, X+1, X+2]}`

**Step 3 — 分配热点验证**
| 分配栈（top_frame） | 增量字节 | 增量计数 | 说明 |
|--------------------|---------|---------|------|
| `global_container_leak.py:13` → dict 构造 | +147,200 (0.14 MiB) | +1,600 | 每迭代创建 1 个新 dict |
| `global_container_leak.py:16` → payload 构造 | +98,848 (0.094 MiB) | +2,689 | 字符串/列表辅助 |
| `global_container_leak.py:11` → range/循环 | +17,376 (0.017 MiB) | +543 | for 循环基础设施 |
| `global_container_leak.py:12` → LEAK_BUCKET.append | +6,880 (0.007 MiB) | +1 | list append 扩容 |

tracemalloc 警告检查：分配点（:13）与保留点（LEAK_BUCKET）行为一致，无分离模式。

**Step 4 — 保留链验证**
| 候选对象 | root_kind | 保留路径摘要 |
|---------|----------|-------------|
| builtins.dict（新插入元素） | module_global:LEAK_BUCKET | 新 dict → LEAK_BUCKET list → 模块 __dict__ 全局变量 |
| builtins.list (LEAK_BUCKET) | module_global_dict | LEAK_BUCKET → 模块 globals() 字典 → 模块对象 |

mind 保留链映射：`global_container_growth` + `module_global:LEAK_BUCKET` → **全局容器无界增长**

**Step 5 — 反事实验证（G3）**
`reachability_counterfactual.verdict: counterfactual_confirmed`
`LEAK_BUCKET.clear()` 后 `reclaimed_ratio=1.0`，所有 800 个 dict 完全释放。

**✅ 结论：根因确认为全局容器 `LEAK_BUCKET` 无界增长。**

### 5.1 应急处置

| 步骤 | 操作 | 执行人 | 时间 | 效果 |

### 5.2 永久修复计划

#### 方案 A：限制最大容量，超出时自动淘汰（最小修复）

```python
MAX_BUCKET_SIZE = 1000

def run_workload(iterations):
    global LEAK_BUCKET
    for index in range(iterations):
        if len(LEAK_BUCKET) >= MAX_BUCKET_SIZE:
            LEAK_BUCKET.pop(0)  # 或 LEAK_BUCKET = LEAK_BUCKET[-MAX_BUCKET_SIZE+1:]
        LEAK_BUCKET.append({
            "index": index,
            "payload": "global-container-leak" * 128,
            "tags": [index, index + 1, index + 2],
        })
    return {"leak_bucket_len": len(LEAK_BUCKET)}
```

#### 方案 B：用 `collections.deque` 替代 list，自动定长（根本修复）

```python
from collections import deque

MAX_BUCKET_SIZE = 1000
LEAK_BUCKET = deque(maxlen=MAX_BUCKET_SIZE)

def run_workload(iterations):
    for index in range(iterations):
        LEAK_BUCKET.append({
            "index": index,
            "payload": "global-container-leak" * 128,
            "tags": [index, index + 1, index + 2],
        })
    return {"leak_bucket_len": len(LEAK_BUCKET)}
```

#### 方案 C：按业务语义确定生命周期，每次运行前清空

```python
def run_workload(iterations):
    LEAK_BUCKET.clear()  # 每次 workload 迭代前清空历史数据
    for index in range(iterations):
        ...
```

#### 修复措施对比

| 修复措施 | 负责人 | 完成时间 | 说明 |

## 三、排查过程

> 排查逻辑：**提出假设 → 收集证据 → 验证或排除 → 逐步收敛到根因**

### 3.1 初始现象

- **来源**：Kuafu 分支 C 诊断任务（`kuafu_C1_mallocfreq.md`）
- **目标进程**：`branch_c_library --loop mallocfreq`（PID 11120）
- **采集到的特征**：
  - 进程持续执行高频 malloc/free 模式
  - 每轮循环分配 500 个小内存块，大小 16-528 字节（随机）
  - 分配后执行 memset 填充
  - 释放一半后重新 malloc 替换
  - 全程持续循环，属于典型的**内存抖动（Memory Churn）**模式

### 3.2 假设驱动排查

#### 假设 A：内存泄漏（Memory Leak）

> 🧪 假设：进程存在真正的内存泄漏，分配的内存未被释放导致 RSS 持续增长

| 检查项 | 操作 | 结论 |
|--------|------|------|
| 分配/释放平衡 | 查看分配模式：每轮分配 500 块 → free 一半 → 再 malloc 替换一半 | ⚠️ 不是严格泄漏，但释放不完全（每轮净增约 250 块活跃内存） |
| 长期趋势 | 每轮净增约 250 块 × 平均 272 字节 ≈ 68KB/轮，RSS 会线性增长 | ⚠️ 持续运行必定导致 RSS 膨胀 |

**❌ 部分排除**：不完全的泄漏（释放一半）解释了 RSS 增长，但核心问题不仅是"泄漏"，更是内存抖动模式本身。

---

#### 假设 B：内存抖动/碎片化（Memory Churn / Fragmentation） ✅ 确认根因

> 🧪 假设：高频 alloc/free 模式导致堆碎片化和缓存污染

**Step 1 — 确认分配模式特征**

| 证据项 | 数据 | 结论 |
|--------|------|------|
| 单次分配大小 | 16-528 字节（随机） | 跨 fastbin（<64B）和 smallbin（64B-1KB）两个区间 |
| 每轮次数 | 500 次 malloc + 250 次 free + 250 次 realloc | 高频操作，1 秒可执行多轮 |
| 填充行为 | memset 填充分配的内存 | 增加 CPU 写入压力，且写入后立即释放 → 缓存浪费 |
| 进程模式 | 持续循环，无退出条件 | 无限期运行，影响持续累积 |

**Step 2 — 分析内存分配器（ptmalloc）行为**

在 glibc ptmalloc 下，16-528 字节的分配主要走 fastbin（16-80B）和 smallbin（>80B 且 <1KB）：
- **Fastbin** 范围（16-80B）：这部分内存释放时不合并，直接放入 fastbin LIFO 链表 → 不触发碎片合并
- **Smallbin** 范围（81-528B）：释放时尝试合并相邻空闲 chunk
- **随机大小组合**：导致 fastbin/smallbin 之间交叉分配，无法高效复用，频繁触发 Top Chunk（主分配区末尾的大块空闲区）分裂

**Step 3 — 缓存污染分析**

```text
每轮操作模型（近似）：
  1. malloc 500 块（随机大小）          → 分配器搜索合适 bin / 分裂 Top Chunk
  2. memset 填充 500 块                 → 数据写入 L1/L2/L3 缓存
  3. free 250 块                        → 释放内存，但缓存行仍被脏数据占用
  4. malloc 250 块重新填充               → 新数据换入，旧缓存行被覆盖
  5. 回到步骤 1（无限循环）              → 缓存持续被"用完即弃"数据污染

影响：
  - 有效缓存利用率下降 30%-70%（取决于工作集大小）
  - 同 CPU 核心上的其他业务进程的缓存命中率受损
```

**Step 4 — 量化评估单轮资源消耗**

| 指标 | 计算过程 | 数值 |
|------|---------|------|
| 每轮分配总字节 | 500 × avg(272B) ≈ 136KB | ~136 KB |
| 每轮释放总字节 | 250 × avg(272B) ≈ 68KB | ~68 KB |
| 每轮净增活跃内存 | 250 × avg(272B) ≈ 68KB | ~68 KB |
| 每轮 memset 写入量 | 500 × avg(272B) ≈ 136KB | ~136 KB（CPU 写入带宽） |
| 预估 1 小时净增 RSS | 68KB × 轮次/秒（假设 2轮/s）× 3600s | ~489.6 MB |
| 预估 6 小时净增 RSS | 同上 | ~2.87 GB |

**✅ 结论：进程 `branch_c_library --loop mallocfreq`（PID 11120）执行的高频 malloc/free 模式，是典型的内存抖动（Memory Churn）行为。根本原因在于其主动设计的 `--loop mallocfreq` 执行逻辑——每轮分配 500 块随机大小的小内存、memset 填充、释放一半后替换另一半，无限循环。此模式导致堆碎片化、CPU 缓存污染、内存分配器压力，且长期运行会导致 RSS 持续增长。**

    void *ptrs[500];
    for (int i = 0; i < 500; i++) {
        size_t size = 16 + rand() % 513;  // 16-528 字节

PoolEntry pool[POOL_SIZE];  // 启动时一次性分配

### B. 关键术语定义

| 术语 | 解释 |
|------|------|
| **Memory Churn（内存抖动）** | 应用程序频繁分配和释放内存的现象，导致分配器压力、碎片化和缓存效率下降 |
| **堆碎片化** | 堆上散布着无法合并的小空闲块，导致连续内存分配失败，堆被迫增长 |
| **Cache Thrashing** | 缓存行被频繁换入换出，有效缓存命中率显著下降 |
| **fastbin / smallbin** | glibc ptmalloc 中用于管理小内存块的 bin 数据结构 |
| **Top Chunk** | 堆末尾的大块空闲区域，分配时被分裂，释放时无法收缩 |

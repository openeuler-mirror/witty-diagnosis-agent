# T1 诊断结果: 验证 SIGBUS on truncated file

## 基本信息
- **任务 ID**: T1
- **任务标题**: 验证 SIGBUS on truncated file
- **故障描述**: mmap 映射文件被 ftruncate 截断后访问映射区域触发 SIGBUS(signal 7)
- **目标容器**: mmap-f2 (Docker)
- **诊断时间**: 2026-05-20 11:08 UTC
- **Access 方式**: docker exec mmap-f2

## 诊断流程

### 1. 构建复现程序 (Reproducer)
编写 C 程序复现 SIGBUS 故障场景：
- `mmap(MAP_SHARED, PROT_READ)` 映射 4096 字节文件
- 确认映射后正常读取文件内容
- 执行 `ftruncate(fd, 0)` 将文件截断至 0 字节
- 再次访问之前映射的虚拟内存区域

### 2. strace 捕获完整系统调用链

```
mmap(NULL, 4096, PROT_READ, MAP_SHARED, 3, 0) = 0x7030e202d000   # 成功映射文件
ftruncate(3, 0)                         = 0                        # 文件被截断至 0
--- SIGBUS {si_signo=SIGBUS, si_code=BUS_ADRERR, si_addr=0x7030e202d000} ---  # 访问映射区域触发 SIGBUS
+++ exited with 1 +++                                                 # 进程退出
```

### 3. SIGBUS 信号详情
- **信号编号**: 7 (SIGBUS)
- **错误码**: `BUS_ADRERR` (非对齐地址/无效物理地址)
- **触发地址**: `0x7030e202d000` (mmap 映射起始地址)
- **触发操作**: 读取已映射但文件已被截断的内存页

### 4. 文件状态对比
| 属性 | mmap 时 | ftruncate 后 |
|------|---------|-------------|
| 文件 `/tmp/test_mmap_file.dat` 大小 | 4096 字节 | **0 字节** |
| mmap 映射区域 | 0x7030e202d000 (4096 字节) | 0x7030e202d000 (4096 字节) |
| 可安全访问范围 | 0x7030e202d000 ~ 0x7030e202dfff | **无** (文件为 0) |

### 5. 核心发现
访问 mmap 映射区域中**超出当前文件大小**的部分时，Linux 内核发送 SIGBUS 信号：
- mmap 映射时文件大小为 4096 字节，映射了 4096 字节的虚拟地址空间
- `ftruncate(fd, 0)` 将文件截断为 0 字节，但映射区域仍存在
- 进程尝试读取 `addr[0]` (虚拟地址 `0x7030e202d000`) 时，内核发现该页对应的文件已无有效数据
- 内核无法返回有效数据 → 发送 `SIGBUS` (signal 7, `BUS_ADRERR`)

### 6. 关键证据
1. **strace 日志**: 完整捕获 `mmap → ftruncate → SIGBUS` 调用链
2. **SIGBUS 信号参数**: `si_signo=SIGBUS, si_code=BUS_ADRERR, si_addr=0x7030e202d000`
3. **文件大小**: `ftruncate` 后为 0 字节（mmap 时 4096 字节）
4. **进程退出码**: exit(1) — 信号处理函数中执行 `_exit(1)` 退出
5. **core_pattern**: `|/wsl-capture-crash %t %E %p %s` (WSL 环境下 core dump 由 wsl-capture-crash 处理)

## 故障复现完整调用链
```
[1] PID: 328  → 进程启动
[2] open → write 4096B → 创建临时文件 /tmp/test_mmap_file.dat
[3] mmap(MAP_SHARED, PROT_READ, 4096) @ 0x7030e202d000 → 映射成功
[4] Pre-truncate read: 'A' → 正常读取映射内容
[5] ftruncate(fd, 0) → 文件被截断至 0 字节
[6] File size: 0 bytes → 确认文件已空
[7] Access mmap[0] → **SIGBUS (BUS_ADRERR)** → 进程捕获信号并退出
```

## 诊断结论
- **故障类型**: SIGBUS on truncated file (已确认)
- **故障原因**: 文件通过 mmap 映射后，被 ftruncate 截断至映射范围以下，访问已截断部分触发 SIGBUS
- **置信度**: 高 (strace 完整捕获 + 程序可控复现)
  - 时间链路: `mmap(0)` → `ftruncate(fd,0)` 时间差 < 1ms
  - 独立证据: strace 日志、信号处理函数捕获、文件大小对比
  - SIGBUS `si_code=BUS_ADRERR` 确认是地址错误而非其他类型 SIGBUS

Witty Diagnosis Agent

Witty 智能诊断 Agent 是 openEuler 社区孵化的开源智能故障诊断平台，基于「假设-验证」（Hypothetico-Deductive）故障排查范式与 Xuanyuan/Fuxi/Dayu/Kuafu/Baize/Nuwa/Shennong/Taiyi 八 Agent 流水线协同架构，覆盖用户态、内核态与硬件三层故障，实现"现象分析 → 根因定界 → 报告生成 → 自愈修复"分钟级、代码行级的全自动诊断闭环。目前已适配 OpenCode 与 xiaoO 两大 Agent 运行时。

02

目录结构

src/witty/ 是插件核心：agents/ 定义 8 个 Agent 角色与双语 Prompt，cli/ 负责安装与自检，guards/ 挂进 OpenCode 会话生命周期做安全护栏，tools/ 与 mcp/ 对接外部检索服务；web/ 是一套相对独立的诊断控制台子系统。src/xiaoO/（暖色节点）不是 TS 代码，而是把同一套 Agent 以 command/*.md + config.toml 的形式适配给 xiaoO 运行时。

03

快速开始

前置条件：Node.js ≥ 20；已安装 OpenCode 或 xiaoO 之一作为宿主 Agent 运行时；Ansible 需提前安装并在 PATH 中可用（witty-diagnosis-agent install 会强校验，未装直接终止）。

1
安装
# 方式一：在线安装（推荐）npm install -g witty-diagnosis-agent@latestwitty-diagnosis-agent install # 方式二：源码一键安装git clone https://atomgit.com/openeuler/witty-diagnosis-agent.gitcd witty-diagnosis-agentbash install.sh # 方式三：离线包一键安装tar -xzvf witty-diagnosis-agent-v<version>.tar.gzcd witty-diagnosis-agent-v<version>bash install.sh
witty-diagnosis-agent install 把插件注册进 OpenCode 并初始化配置；支持 --dry-run 只预览变更、--language zh|en 指定输出语言（非交互终端默认 zh）。install.sh 额外负责环境检查、依赖安装与 npm run build。
2
使用
# 基于 OpenCode启动 OpenCode → /agents 选择 Xuanyuan → 描述故障现象 # 基于 xiaoO启动 xiaoO → Tab 切换 Xuanyuan → 描述故障现象 # 环境自检witty-diagnosis-agent doctor # 独立诊断 Web 控制台（可选）cd src/witty/web && bash init.sh && bash start.shdocker compose -f src/witty/web/docker-compose.yml up -d

Xuanyuan（总控）调度 Shennong（检索历史案例）→ Fuxi（生成结构化排查计划）→ Dayu（并发调度执行节点）→ Kuafu（加载 Skill 深入节点拉取指标）→ Baize（汇总证据链输出报告）；按需触发 Nuwa（安全规则下自动修复）。诊断完成后同时生成 HTML 与 Markdown 两种格式的报告。

3
测试
npm run typecheck # tsc --noEmitcd src/witty/web/server && npm test # node --test src/**/*.test.ts

常规单元测试只有 6 个 *.test.ts，集中在 web/server 与 tools/lightrag；test/ 目录下 18 个场景是"故障注入 + 期望诊断报告"的端到端验证床，需要真实故障环境，不是常规单测。

环境变量

来源：.env.example（插件核心，20 项）+ src/witty/web/docker-compose.yml（Web 控制台另有一套）。

变量名用途默认值必需
DEEPSEEK_API_KEY核心 LLM 服务密钥—是
DEEPSEEK_BASE_URLDeepSeek API 端点https://api.deepseek.com/否
DEEPSEEK_MODEL模型名称deepseek-chat否
LANGFUSE_PUBLIC_KEY / SECRET_KEYLLM 调用追踪凭据（可选）—否
LANGFUSE_HOSTLangfuse 服务地址cloud.langfuse.com否
CUSTOM_SKILL_PATHS自定义 Skill 存放目录{project_root}/custom_skills否
LIGHTRAG_ENDPOINT太乙(Taiyi) 运维问答检索服务端点http://localhost:9621否*
LIGHTRAG_API_KEY / _API_KEY_HEADERLightRAG 鉴权密钥 + 请求头名X-API-Key否
LIGHTRAG_QUERY_MODE检索模式：local/global/hybrid/naive/mix/bypassmix否
LIGHTRAG_TIMEOUT_MS单次检索超时（毫秒）30000否
LIGHTRAG_RESPONSE_TYPE期望回答格式（透传给 LightRAG）Multiple Paragraphs否
LIGHTRAG_INCLUDE_CHUNK_CONTENT是否附带引用 chunk 原文true否
CASE_KB_ID / CASE_API_BASE_URL / CASE_ACCESS_KEY神农(Shennong) Agent 检索的知识库 ID / 地址 / 密钥—否*
CASE_API_TIMEOUT_MS / CASE_TOP_K检索超时与返回条数—否
CASE_CASES_DIR本地 case 缓存目录—否

* LIGHTRAG_* 仅在太乙问答功能启用时必需；CASE_* 仅在神农历史案例检索启用时必需。Web 控制台另有独立环境变量（PORT、DB_CLIENT、COOKIE_SECRET 等），见下一节 docker-compose.yml。

05

部署

部署方式配置文件说明
CLI 插件（在线安装） npm install -g + witty-diagnosis-agent install 注册进宿主 OpenCode/xiaoO 配置，随宿主进程运行，无需常驻服务
CLI 插件（源码/离线一键安装） install.sh 环境检查 → 依赖安装 → npm run build（tsup）→ 写入插件配置
Web 诊断控制台（Docker） src/witty/web/docker-compose.yml 前端 Nginx 反代 + 后端 Fastify 单实例；默认 SQLite 命名卷持久化，DB_CLIENT=mysql 可切云化 MySQL；--profile qa 按需启用依赖 LightRAG 的问答模块
Web 诊断控制台（本地开发） src/witty/web/{init.sh,start.sh} 本地起前后端（Vite dev server + tsx watch），便于调试
关键差异：诊断执行阶段（Kuafu 等）严格只读，仅 Nuwa 自愈阶段按安全规则申请操作权限，且变更必经用户审批确认。

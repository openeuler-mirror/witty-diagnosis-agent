# 用户需求描述 (User Requirements Description)
1. 基于witty-diagnosis-agent创建一个web交互的界面，实现
故障任务诊断，包括如下功能模块：
（1）新建故障诊断任务：
用户可以通过填写故障信息，选择在线或离线方式进行诊断。具体需求如下：
- **基础信息填写**：
  - **任务描述（故障现象）**：必填项，多行文本输入，用于描述具体的故障表现（例如：02:14 起 Nginx 大量返回 502，前端下单失败...）。
  - **故障时间**：必填项，支持灵活输入，可以是具体的时间点或时间段，也可以是不确定的时间段，遇到不确定的时间段时需要模型自行判断。
  - **运维类型**：必填项，提供“在线诊断”和“离线分析”两种模式供用户选择。

- **在线诊断模式（连接目标主机自动采集数据）**：
  - 当选择“在线诊断”时，需填写目标主机连接信息。
  - **必填字段**：主机 IP、账号（如 root）、密码。
  - **选填/默认字段**：SSH 端口（默认通常为 22）。
  - **辅助功能**：提供“测试连通性”按钮，用于验证输入的主机凭证是否能成功连接。
  - **安全保障**：界面需有明确提示语，告知用户“凭据将加密存储，报告与日志中自动脱敏。仅本次使用，不保存”。

- **离线分析模式（上传已有日志进行分析）**：
  - 当选择“离线分析”时，展示日志上传区域。
  - **上传交互**：支持点击区域添加日志文件。
  - **格式支持**：明确提示支持 `.log` / `.tar.gz` / `.zip` 格式的文件。
（2）故障诊断任务执行：
  - 用户点击“执行诊断”按钮后，调用witty-diagnosis-agent（即：xuanyuan agent）继续任务后台执行；
  - 后台任务会不断执行，更新状态，会有显示百分比。
  - 当用户查看执行任务过程中，可以看到日志的执行过程。
（3）故障诊断任务列表：
  - 用户可以在任务列表中查看所有已创建的故障诊断任务，包括任务状态、任务进度、任务创建时间等。
  - 支持同时下发多个任务。
（4）用户任务隔离：
- 每个用户只能查看和管理自己创建的任务。
- 任务列表中，每个任务都有一个唯一的任务ID，用户可以通过任务ID来查看任务详情。

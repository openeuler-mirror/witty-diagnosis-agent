## 四、发现并修复的问题

### 问题 1：阶段进度条异常跳转

**状态**：✅ 已修复

**症状**：调用 Fuxi-Sub 时进度直接跳到 `故障定位 78%`，全程卡在 `数据分析 55%` 不动。

**根因**：
- 初始 prompt 含 `"Fuxi→Dayu→Kuafu→Baize 并生成可视化 RCA 报告"`，文本关键词扫描同时匹配了所有阶段
- `SUBAGENT_STAGE` 映射大小写不敏感（实际 subagent_type 为 `"Fuxi-Sub"`/`"Dayu"`/`"Baize"`，映射键为 `"fuxi-sub"`/`"dayu"`/`"baize"`）

**修复方案**：

| 文件 | 改动 |
|------|------|
| `event-synthesizer.ts` | 文本关键词只保留到 `数据采集`；`数据分析/故障定位/生成报告` 从文本扫描中移除 |
| `event-synthesizer.ts` | 新增 `SUBAGENT_STAGE` 映射 + 查询时 `sub.toLowerCase()` |
| `event-synthesizer.ts` | 工具事件处理中用 `SUBAGENT_STAGE` 替代 `scanText` |

**修复效果**：

```
修复前：15s → 数据分析55% → 全程卡住不动
修复后：30s → 数据采集25% → 150s → 数据分析55% → 360s → 故障定位78% → 510s → 完成100%
```

---

### 问题 2：重试时 SSH 凭据丢失

**状态**：✅ 已修复

**症状**：失败任务重试后，Fuxi-Sub 收不到连接信息，向用户索要凭据 → `question` 工具不可用 → 诊断失败。

**根因**：`runner.ts` 的 `finally` 块无条件调用 `vault.wipe(taskId)`。重试时 `vault.reveal()` 返回 null，prompt 不带 SSH 凭据。

**修复方案**：仅成功时擦除凭据，取消/失败/超时保留。

```typescript
// 修复前
} finally { vault.wipe(taskId); }

// 修复后
} finally {
  if (gotReport) { vault.wipe(taskId); }
}
```

| 场景 | 修复前 | 修复后 |
|------|:----:|:----:|
| 诊断成功 | 擦除 | 擦除 |
| 用户取消 | 擦除 | **保留** |
| 超时失败 | 擦除 | **保留** |
| 异常失败 | 擦除 | **保留** |

---

### 问题 3：重试时报 `Server exited with code 1`（端口冲突）

**状态**：✅ 已修复

**症状**：取消后立即重试 → `Failed to start server. Is port 4096 in use?`

**根因**：

- 所有任务共用端口 4096，并发上限 `maxConcurrent=4`，但端口只有 1 个
- 取消时只发 abort 不杀进程，端口仍被占用

**修复方案**：

```typescript
// 修复前：所有任务用默认端口 4096
createOpencode({ hostname: "127.0.0.1" })

// 修复后：每个任务用 getAvailableServerPort 分配唯一端口
const { port } = await getAvailableServerPort(4096);
createOpencode({ hostname: "127.0.0.1", port })
```

| 场景 | 修复前 | 修复后 |
|------|:----:|:----:|
| 任务 1-4 并发 | 全部冲突 → 只能跑 1 个 | 4096/4097/4098/4099 各用各的 |

---

### 问题 4：连通性测试为硬编码骨架

**状态**：✅ 已修复

**症状**：随便输入密码都返回 `{"ok":true}`。

**根因**：`routes/tasks.ts` 中硬编码 `await new Promise(r => setTimeout(r, 600)); return { ok: true };`

**修复方案**：替换为真实两层探测：

1. **TCP 端口检测**：`timeout 3 nc -zv host port` 或 bash `/dev/tcp`
2. **凭据验证**：`sshpass + ansible -m ping` 验证 SSH 密码

附带修复：
- **127.0.0.1 绕过问题**：ansible 对 localhost 自动切 `connection=local` 绕过 SSH，用 `127.0.0.2` 替代
- **ControlMaster 缓存问题**：用唯一 `ControlPath=/tmp/ansible-conn-<uuid>.sock` 防止复用

| 场景 | 修复前 | 修复后 |
|------|:----:|:----:|
| 正确密码 | `ok:true` | `ok:true` |
| 错误密码 | `ok:true` ❌ | `认证失败` ✅ |
| 不可达主机 | `ok:true` ❌ | `连接超时` ✅ |

---

### 问题 5：`start.sh` 重复执行端口冲突

**状态**：✅ 已修复

**症状**：重复执行 `bash start.sh` 时后端报 `EADDRINUSE: address already in use`。

**修复方案**：启动前检查并清理旧进程，健康检查超时给出明确提示。

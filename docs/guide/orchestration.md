# 协作与编排 (Orchestration)

本项目不依赖“单个 Agent 一次性把问题做完”。在运维诊断中，更常见的有效路径是：

1. 先把故障现场信息收集齐（时间点、环境、日志、变更）。
2. 基于现象提出多个候选假设，并行验证。
3. 汇总证据链，收敛根因，再进入修复与验证。

## 并行分析范式

“假设-验证”的并行流程通常包含三个角色：

- **规划者**：根据现象与上下文提出多个假设，定义每条假设需要的验证证据。
- **执行者**：围绕各自假设执行采集与分析动作，输出可核验的证据。
- **汇总者**：汇总并对齐证据，排除干扰项，输出可复现的根因结论。

## 与核心组件的对应关系

该协作方式与核心组件的对应关系如下：

- Commander：负责建上下文、拆任务、调度执行。
- Investigator：负责并发采集、分层定界。
- Analyst：负责证据链推理与根因收敛。
- Strategist/Guardian/Operator/Auditor：负责修复与验证链路。

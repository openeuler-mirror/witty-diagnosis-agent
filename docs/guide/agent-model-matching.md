# 模型支持 (Model Support)

witty-diagnosis-agent 作为一个故障诊断插件，其推理能力高度依赖于底层大模型的性能。为了获得最佳的诊断效果，我们建议根据不同的 Agent 角色选择最合适的模型。

## 推荐模型配置

根据我们的内部验证与测试，以下是各 Agent 角色的推荐模型配置：

| Agent 角色 | 推荐模型 | 适用场景 | 验证效果 |
| :--- | :--- | :--- | :--- |
| **Fuxi (伏羲)** <br> *诊断规划* | **GLM-4 / GLM-4-Plus** | 复杂故障场景的理解、多维度上下文分析、生成结构化诊断计划 | **优秀** <br> 能准确识别 95% 以上的故障意图，生成的计划逻辑严密。 |
| **Dayu (大禹)** <br> *任务编排* | **DeepSeek-V3 / R1** | 将高层计划拆解为可执行的指令序列、并行任务调度、工具调用 | **优秀** <br> 代码/指令生成准确率高，能有效处理复杂的依赖关系。 |
| **Baize (白泽)** <br> *根因分析* | **GLM-4 / GLM-4-Plus** | 跨数据源关联分析、逻辑推理、生成最终诊断报告 | **优秀** <br> 在中文语境下推理能力强，能生成清晰易懂的根因分析报告。 |
| **Nuwa (女娲)** <br> *方案修复* | **DeepSeek-V3 / R1** | 生成代码修复补丁、编写自动化修复脚本 | **优秀** <br> 代码生成质量高，生成的修复脚本通过率高。 |

> **注**：以上推荐基于我们在特定数据集上的验证结果。实际效果可能因具体场景而异。

## 配置指南

您可以在 `witty-diagnosis.jsonc` 或 OpenCode 的插件配置中指定各模块使用的模型。

### 方式一：OpenCode 全局配置 (推荐)

在 OpenCode 的设置中，为 `witty-diagnosis-agent` 插件配置默认模型：

```json
{
  "plugins": {
    "witty-diagnosis-agent": {
      "model": "glm-4" // 设置全局默认模型
    }
  }
}
```

### 方式二：精细化配置 (witty-diagnosis.jsonc)

您可以在项目根目录下的 `witty-diagnosis.jsonc` 文件中，为不同的模块指定不同的模型（如果插件支持）：

```jsonc
{
  "modules": {
    "commander": { // 对应 Fuxi
      "model": "glm-4"
    },
    "investigator": { // 对应 Dayu/Kuafu
      "model": "deepseek-v3"
    },
    "analyst": { // 对应 Baize
      "model": "glm-4"
    },
    "remediator": { // 对应 Nuwa
      "model": "deepseek-v3"
    }
  }
}
```

## 验证方式

配置完成后，您可以通过以下方式验证模型是否生效及效果：

1.  **执行诊断**：在 OpenCode 中输入 `diagnosis-agent test-skill data-collector` 或发起一次真实的故障诊断。
2.  **查看日志**：检查插件输出的日志，确认当前调用的模型名称。
3.  **评估结果**：观察 Agent 生成的计划、执行的命令以及最终的报告，对比上述表格中的预期效果。

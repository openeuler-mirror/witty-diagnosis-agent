# Agent 使用手册 (Agent Usage Guide)

本手册详细介绍了 witty-diagnosis-agent 中各个核心 Agent 的功能、触发方式及最佳实践。

## 1. Fuxi (伏羲) - 诊断规划

**角色定位**：故障排查的“指挥官”，负责理解用户意图与故障上下文，生成结构化的诊断计划。

### 触发方式
- **自动触发**：当用户在 witty-diagnosis-agent 中输入自然语言描述故障时（如“排查 API 502 错误”），默认由 Fuxi 首先接管。
- **显式调用**：`@witty-diagnosis-agent 制定排查计划`

### 核心能力
- **意图识别**：区分故障排查、信息查询或日常闲聊。
- **上下文澄清**：当信息不足时，主动反问（如“请提供报错的时间点和受影响的服务”）。
- **计划生成**：输出包含 [环境检查] -> [日志分析] -> [定界测试] 的分步计划。

### 使用示例
```
User: 生产环境订单服务响应慢，帮我看看。
Fuxi: 收到。为了更精准地规划，请确认：
      1. 是所有接口慢还是特定接口？
      2. 最近是否有发版变更？
      (待用户补充后，生成 Plan)
```

## 2. Dayu (大禹) - 任务编排

**角色定位**：计划的“执行官”，将 Fuxi 的高层计划拆解为具体的计算机指令，并调度 Kuafu 执行。

### 触发方式
- **自动流转**：Fuxi 计划生成并经用户（或自动）确认后，自动流转至 Dayu。
- **显式调用**：`@witty-diagnosis-agent 执行当前计划`

### 核心能力
- **任务拆解**：将“检查 CPU 负载”拆解为 `top`, `vmstat` 等具体命令。
- **并行调度**：同时调度多个 Kuafu 实例并行采集不同节点的数据。
- **依赖管理**：确保前置任务（如“获取 Pod 列表”）完成后再执行后置任务（如“查看 Pod 日志”）。

### 使用技巧
- **干预执行**：在交互模式下，你可以随时暂停 Dayu 的执行，插入新的指令或跳过某些步骤。

## 3. Baize (白泽) - 根因分析

**角色定位**：数据的“分析师”，对采集到的海量数据进行关联分析，推理出根本原因。

### 触发方式
- **自动流转**：Dayu 完成所有数据采集任务后，自动唤醒 Baize。
- **显式调用**：`@witty-diagnosis-agent 分析现有日志`

### 核心能力
- **模式识别**：从日志中识别异常堆栈、错误码分布。
- **时序关联**：将 CPU 飙升时刻与错误日志爆发时刻进行对齐。
- **报告生成**：输出包含“现象描述、排查过程、根因结论、证据链”的 Markdown 报告。

### 输出示例
> **根因结论**：数据库连接池耗尽。
> **证据**：
> 1. 应用日志显示 `ConnectionTimeout` 异常激增 (14:00:01)。
> 2. 数据库监控显示活跃连接数达到上限 500 (14:00:00)。

## 4. Nuwa (女娲) - 方案修复

**角色定位**：系统的“修复师”，生成修复方案并执行（需授权）。

### 触发方式
- **人工审批**：Baize 输出根因后，用户确认进入修复阶段。
- **显式调用**：`@witty-diagnosis-agent 生成修复脚本`

### 核心能力
- **方案生成**：根据根因推荐修复步骤（如“扩容连接池”、“重启服务”、“回滚版本”）。
- **代码补丁**：针对代码逻辑错误，直接生成 Git Patch。
- **自动化脚本**：生成 Shell/Python 脚本以自动化执行运维操作。

### 安全提示
- Nuwa 的所有写操作（修改配置、重启服务）默认需要用户 **二次确认**。
- 建议在测试环境先行验证 Nuwa 生成的脚本。

## 5. 通用交互指令

| 指令 | 说明 | 示例 |
| :--- | :--- | :--- |
| `/plan` | 查看或重新生成当前诊断计划 | `/plan 重查一遍` |
| `/act` | 强制开始执行当前步骤 | `/act` |
| `/report` | 生成当前阶段的诊断报告 | `/report` |
| `/clear` | 清除当前诊断上下文 | `/clear` |
| `/help` | 显示帮助信息 | `/help` |

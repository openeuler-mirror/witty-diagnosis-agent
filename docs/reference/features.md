# 功能列表 (Features)

## 故障诊断能力

本项目基于**OS 全栈（硬件层→内核层→系统服务层）** 全维度故障模式梳理，系统构建故障诊断能力（通过表格 “Skill” 字段承载），诊断能力随故障场景迭代、技术升级持续演进，具体故障模式及对应诊断信息如下表所示。

| 故障域    | 故障模式             | 故障描述                                                                                                                                                                                    | 故障影响                                                                 | 诊断方式 | Skill                               | 状态  |
| ------ | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ---- | ----------------------------------- | --- |
| OS内核   | 系统Crash          | 因内核代码异常、硬件故障、驱动冲突、内存溢出或关键进程异常终止等原因，导致内核无法正常执行指令、失去对系统资源的控制，进而引发系统突然宕机、重启或陷入无响应状态的严重故障。典型场景包括死锁、Hard Lockup、Hung Task、Kernel Panic、PCIe 总线错误、IO Hang、OOM等。                               | 业务中断、数据丢失                                                            | 离线   | vmcore-analysis                     | 已支持 |
| CPU调度  | 用户态/内核态CPU 过载    | 系统 CPU 利用率持续处于高位（用户态、系统态、iowait、softirq 等任一维度长期接近 100%），CPU 调度队列长度持续大于 CPU 核心数，导致任务调度延迟增大、响应能力急剧下降。                                                                                     | 业务处理能力急剧下降                                                           | 离线   | cpu-scheduling-diagnosis            | 已支持 |
| CPU调度  | cgroup组CPU 过载    | 进程所属 cgroup（如 Kubernetes Pod、Docker 容器、系统服务资源组）受 CPU 限制（cpu.cfs_quota_us/cpu.shares/cpuset 等），组内进程总 CPU 使用率超过配额上限，或因 CPU 共享争抢导致调度资源不足；内核通过节流（throttle） 控制组内 CPU 占用，引发任务执行延迟、调度排队变长。     | 容器/服务性能下降                                                            | 离线   | cpu-scheduling-diagnosis            | 已支持 |
| 内存     | OOM              | 系统物理内存与交换空间持续耗尽，内核内存资源不足，无法满足进程或内核自身的内存分配请求。为防止系统整体崩溃，内核触发 OOM killer 机制，根据进程内存占用、优先级等策略选择并强制杀死部分用户进程；若内核态内存极度紧缺，还可能引发内核级内存分配失败，直接导致系统 hang 或 panic。                                    | 1、应用进程异常退出，业务中断。2、内核无法分配内存，触发 hung task、soft lockup 甚至 kernel panic。 | 离线   | linux-oom-analyzer                  | 已支持 |
| 网络     | 网络不通             | 主机 / 设备之间无法建立网络连接，表现为 ping 丢包或完全不通、TCP 连接超时、端口无法访问；路由、ARP、DNS、防火墙、链路状态等任一环节异常，导致网络报文无法正常转发、接收或响应，业务网络交互中断。                                                                              | 业务服务不可用                                                              | 在线   | network-diagnosis                   | 已支持 |
| 硬盘     | UNC/UF 坏道        | 硬盘扇区出现 UNC（Uncorrectable Error）/ UF（Uncorrectable Fault） 级不可纠正错误，扇区数据校验彻底失败，硬盘固件用尽所有纠错与重试机制仍无法读写。检测工具扫描显示红色 UNC/UF 标记，系统日志持续报 I/O error，SMART 中 C5（待重映射）、C6（离线不可纠正） 计数异常升高，扇区被标记为永久不可用。 | 数据永久丢失、文件系统崩溃、业务直接中断                                                 | 离线   | disk-diagnosis-by-log               | 已支持 |
| 文件系统   | 文件系统损坏           | 文件系统元数据（超级块、inode、目录项、位图等）因磁盘坏道、掉电、内核异常、强制重启、IO 错误或软件缺陷发生不一致或破坏，导致内核无法正常解析文件系统结构。系统会触发文件系统自检失败、报错 filesystem error、ext4_journal 异常，严重时文件系统被内核自动挂载为只读模式（read-only），或无法挂载、目录乱码、文件丢失。      | 读写能力异常、业务进程异常                                                        | 离线   | offline-file-system-fault-diagnosis | 已支持 |
| Docker | 容器异常退出           | 容器在运行过程中未按正常流程终止，意外退出并产生非 0 退出码，常见原因包括：应用内部崩溃、OOM 被系统杀死、配置错误启动失败、依赖服务不可用、端口冲突、权限不足、健康检查连续失败、底层资源异常（CPU / 磁盘 / 网络故障）等。表现为容器状态变为 Exited，Pod 重启次数增加，docker ps -a/crictl ps 显示异常退出记录。       | 业务服务中断                                                               | 离线   | docker-fault-analysis               | 已支持 |
| Docker | 容器cgroup pid资源耗尽 | 容器所属 cgroup 的 PID 配额（pids.max） 达到上限，容器内进程 / 线程总数超出限制，内核拒绝创建新进程或线程，导致容器内无法 fork、clone 新任务。                                                                                               | 无法创建新请求处理进程、协程、定时任务、脚本子进程，业务请求直接报错或阻塞                                | 离线   | docker-fault-analysis               | 已支持 |
| 系统安全   | SELinux 策略拒绝     | SELinux 在 Enforcing 模式下根据 Type Enforcement 策略检查进程的每个系统调用。若进程尝试访问其 SELinux 上下文（label）无权限的资源，操作被拒绝（EACCES）并记录到 audit.log，即使 DAC 权限允许也无法访问。                                                | 业务访问被拒                                                               | 离线   | linux-security-diagnosis            | 已支持 |
| 启动引导   | GRUB引导失败         | GRUB 引导加载程序在读取配置文件（grub.cfg）、加载内核镜像（vmlinuz）或初始 ramdisk（initrd）时失败。常见原因：/boot 分区损坏、GRUB MBR/GPT 记录被覆盖、grub.cfg 语法错误。                                                                    | 开机卡在 GRUB 或出现 file not found，无法进入系统                                  | 离线   | grub-ibmc-diagnosis                 | 已支持 |
| 硬盘     | 预失效              | 硬盘在完全失效前，通过 S.M.A.R.T 信息、固件自检或系统日志上报提前失效预警，表现为：重映射扇区计数上升、待映射扇区增加、读写错误率升高、硬件校验异常、硬盘内部容错机制频繁触发等。虽尚未完全宕机，但介质可靠性已显著下降，属于即将发生硬件故障的高危预警，通常对应 RAID 卡 / 带外管理中的 Predictive Failure 告警。           | 读写性能与稳定性下降、数据读写故障风险升高                                                | 在线   | 开发中                                 | 开发中 |
| 内存条    | GPIO中断上报FATAL级故障 | 内存控制器通过 GPIO 引脚向 BMC/OS 上报不可恢复的硬件故障信号。BIOS 在下次启动时执行内存隔离（Memory Scrubbing + DIMM 下线），导致系统可用内存骤减。                                                                                         | 系统异常复位，BIOS 隔离异常内存，大块内存被隔离后可能引发内存不足                                  | 离线   | 开发中                                 | 开发中 |
| 内存条    | GPIO 中断上报CE故障    | 内存 ECC 检测到可纠正错误，通过 GPIO 中断通知 OS。若短时间内 CE 计数超过阈值，触发 CE 风暴，rasdaemon 持续记录，内核可能将该内存页标记为降级。                                                                                                 | 大量可纠正错误可能导致 CE 风暴                                                    | 离线   | 开发中                                 | 开发中 |
| 内存条    | 空闲页 UCE 故障       | 系统空闲内存页发生不可纠正的多比特 ECC 错误。内核通过内存巡检（memory scrub）发现后，调用 hwpoison 机制将该物理页标记为 poison，从可用内存池中移除。                                                                                             | 内存页隔离，系统运行受影响                                                        | 离线   | 开发中                                 | 开发中 |
| 电源     | 电压异常             | PSU（电源供应单元）输出电压偏离额定范围，BMC 通过 IPMI 传感器检测并上报。CPU/内存控制器为防止过压损坏，激活电压保护机制，自动降低运行频率（降频）。                                                                                                      | CPU 降频，性能下降                                                          | 离线   | 开发中                                 | 开发中 |
| 电源     | 电源掉电             | PSU 完全断电，系统在无 UPS 保护时立即失去供电。内存中的 dirty page、数据库 WAL buffer 等未持久化数据全部丢失，系统下次启动时需要执行文件系统 fsck 和数据库崩溃恢复。                                                                                   | 系统进程中断，内存/缓存数据丢失                                                     | 离线   | 规划中                                 | 开发中 |

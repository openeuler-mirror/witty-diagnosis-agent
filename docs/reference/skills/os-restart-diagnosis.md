# 背景：操作系统异常重启是企业IT稳定性的“隐形威胁”

操作系统重启故障是企业IT环境中常见但危害巨大的问题，它可能导致业务中断、数据丢失和服务可用性下降。无论是外部供电异常、人为操作失误、内核自保机制触发还是硬件故障，重启事件往往难以预测且排查复杂。快速准确地定位重启根因，不仅能缩短故障恢复时间，更能防止类似问题重复发生，对保障企业IT系统的稳定性和可靠性具有重要意义。

# 问题与挑战：OS重启故障排查的四大核心困境

1. **重启事件信息碎片化，证据收集困难**
   重启故障的相关信息分散在系统日志、带外管理日志、硬件监控等多个来源，格式各异且时间戳可能不同步。传统排查方法难以在短时间内整合这些碎片化信息，导致关键证据丢失或分析不全面。

2. **重启场景多样，根因定位复杂**
   操作系统重启可能由多种原因引起，从外部供电中断到内核崩溃，从人为操作到硬件故障，每种场景的特征和排查方法都不同。缺乏系统化的场景分类和诊断流程，容易导致误判或漏判。

3. **故障时间链难以重建，因果关系模糊**
   重启事件发生后，系统状态被重置，故障发生前的关键信息可能被覆盖或丢失。传统方法难以重建完整的故障时间链，无法清晰呈现从异常信号到重启触发的全过程，导致因果关系模糊。

4. **跨层级故障传播，单一维度分析效果有限**
   重启故障往往涉及多个层级，如硬件、内核、系统服务等。单一维度的分析难以捕捉跨层级的故障传播路径，可能导致根因定位不准确，解决方案针对性不强。

# 智能诊断Agent：破解OS重启故障的核心诊断能力

面对上述挑战，Witty智能诊断Agent提供了全新的解决方案：

* **全量信息采集与场景指纹识别**：通过自动化手段一次性采集带外电源事件、重启历史、内核日志、崩溃转储与硬件异常信号，基于关键输出自动生成重启故障指纹，并映射到具体场景类型，实现快速初步定位。

* **分场景深度下钻分析**：针对不同重启场景（外部供电异常、人为操作、内核自保、内核崩溃、硬件故障），采用专门的分析方法和验证标准，实现精准的场景化诊断。

* **反思与交叉验证机制**：通过严格区分症状、触发机制和根因，主动挑战当前假设，从系统日志、带外管理日志、硬件/监控指标等多源证据进行交叉验证，确保结论的可靠性。

* **完整故障链重建**：构建从先导事件到重启触发再到恢复的完整时间链，清晰呈现故障的演进过程和因果关系，为修复和预防提供全面依据。

# 使用流程

## 前置要求

### 网络连通要求
- 确保智能诊断Agent与目标服务器之间网络连通，以便执行诊断脚本并获取系统状态的完整信息

### 权限要求
- 需要以`root`或`sudo`权限执行诊断脚本和命令，以获取完整的系统和硬件信息

### 工具安装要求
- 确保目标服务器已安装以下工具：`kexec-tools`（用于kdump）、`lm_sensors`（用于硬件监控）

### 数据准备要求
- 若已知重启发生时间，建议提前记录时间窗口，以便精准分析
- 若涉及特定硬件或系统服务，建议准备相关设备信息
- 若涉及变更操作，建议准备变更时间和内容

## 操作步骤

- 启动 **OpenCode**。

- 执行`/agents`命令选择`Xuanyuan`Agent。
  
- 输入故障问题描述，并**明确指定故障场景和相关信息**，示例如下：
  
  ```shell
  服务器在今天上午10:30左右突然重启，业务中断约5分钟，请帮我分析根因并给出修复建议。
  ```

- 系统将自动执行**智能诊断**流程，按四阶段进行分析并生成综合诊断报告。

- 诊断完成后，查看完整的诊断分析报告，报告包含故障时间链、根因链、证据清单和修复建议。

# 总结

操作系统重启故障的排查难点在于其触发机制的多样性和证据的分散性，传统方法往往难以在复杂环境中快速定位根本原因。重启事件可能源于外部环境变化、硬件异常、系统内核问题或人为操作，每一类原因都需要不同的分析视角和技术手段。

Witty智能诊断Agent采用分阶段诊断策略，通过全量信息采集建立故障指纹，结合场景化深度分析和多源证据交叉验证，实现了重启故障的精准定位。这种系统化的诊断方法不仅提升了故障分析的效率，更重要的是能够构建完整的故障演进链条，为问题修复和预防性维护提供了可靠的技术支撑。

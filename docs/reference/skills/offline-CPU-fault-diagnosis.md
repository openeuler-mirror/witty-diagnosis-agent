# 背景：离线CPU故障诊断成为服务器运维的"关键突破口"

在企业级服务器运维中，CPU作为计算核心，其稳定性直接关系到业务系统的运行效率和可靠性。然而，CPU故障呈现出多层次、多维度的复杂特征，从硬件物理损坏到微码缺陷，从温度异常到互连总线故障，各类问题交织在一起。传统的CPU故障排查依赖运维人员对硬件架构、内核机制和日志分析的深入理解，需要在海量离线日志中寻找关键线索，过程耗时且技术门槛极高。快速定位和解决CPU故障的能力，已成为衡量企业运维水平的重要指标。

# 问题与挑战：离线CPU故障诊断的四大核心困境

1. **故障溯源复杂，物理定位困难**
   CPU故障表现形式多样，从系统层面的内核Panic、Soft Lockup到硬件层面的MCE错误、温度异常，各类现象背后可能隐藏着CPU物理损坏、散热失效、微码缺陷等多种根因。传统排查往往只能定位到"CPU故障"的模糊结论，难以精确到Socket/Core级别的物理坐标。

2. **多源日志异构，时序对齐困难**
   CPU故障诊断涉及iBMC硬件日志、InfoCollect系统日志、OS Messages内核日志等多源异构数据。不同日志格式、时间戳差异和系统时区问题，导致时序对齐难度大，难以构建完整的故障传导链。

3. **证据链不完整，结论可靠性低**
   传统排查往往依赖单一日志源的证据，缺乏多源交叉验证机制。在日志不全或证据不足的情况下，容易做出"疑似故障"的模糊判断，无法为硬件更换和修复提供确凿依据。

4. **技术要求专业，运维门槛高**
   CPU故障诊断需要深入理解CPU架构、微码机制、iBMC管理系统和内核原理等专业知识。中小团队和普通运维人员往往缺乏这类专业能力，面对复杂故障只能依赖原厂支持，延长故障恢复时间。

# 智能诊断Agent：破解离线CPU故障的核心诊断能力

面对上述挑战，Witty智能诊断Agent提供了全新的解决方案：

* **时序关联与传导链重建**：通过确定故障零点(T0)，将iBMC传感器读数、内核报错和系统日志统一映射到绝对时间轴，构建完整的事件序列矩阵和故障传导链，实现从宏观到微观的精准定位。

* **多源交叉验证机制**：采用"孤证不立原则"和"逻辑闭环原则"，要求每个物理级故障结论必须有至少两个独立数据源支撑，通过根因证据校验表(E1/E2/E3)确保结论的可靠性。

* **物理级精准定位**：突破传统"CPU故障"的模糊描述，通过证据追踪实现Socket→Core→Cache级别的三维物理坐标定位，为硬件更换提供精确指导。

* **场景化诊断脚本体系**：提供覆盖CPU硬件故障、过热、微码错误、缓存错误、频率调节、互连错误和电压调节七大场景的专用诊断脚本，实现针对性的深度分析。

# 使用流程

## 前置要求

### 文件准备要求
- 需要准备从服务器收集的标准日志文件，包括：
  - iBMC硬件日志（传感器数据、事件日志）
  - InfoCollect系统日志（系统信息、配置数据）
  - OS Messages内核日志（内核报错、系统事件）
- 确保日志文件完整且包含故障发生时间段的记录

### 数据准备要求
- 若已知故障发生时间，建议提前记录故障时间窗口，以便精准分析
- 若涉及特定服务器或设备，建议准备服务器型号、CPU型号等硬件信息

## 操作步骤

- 启动 **OpenCode**。

- 执行`/agents`命令选择`Xuanyuan`Agent。
  
- 提供日志文件路径并描述故障现象，示例如下：
  
  ```shell
  我的服务器因CPU过热导致宕机，请帮我分析/path/to/logs目录下的离线日志，找出具体的故障根因和修复建议。
  ```

- 系统将自动执行**智能诊断**流程，依次完成日志扫描分析、场景分类、深入分析和根因校验。

- 诊断完成后，查看完整的诊断分析报告，报告包含故障摘要、故障时间链、故障传播链、技术分析与根因、修复建议。

# 总结

离线CPU故障诊断的核心难点在于，它依赖历史日志进行回溯分析，无法实时获取系统状态和进行动态验证。多源异构日志的时序对齐、证据链完整性验证以及物理级精准定位，构成了离线诊断的三大技术挑战。传统排查方式往往只能得出"疑似故障"的模糊结论，难以满足硬件更换和修复的精确要求。

Witty智能诊断Agent通过**时序关联分析**和**多源交叉验证**，将离线CPU故障诊断过程标准化：从确定故障零点(T0)开始，构建完整的事件序列矩阵，通过Socket→Core→Cache的三维物理坐标定位，实现从宏观到微观的精准诊断。这种基于数据驱动的诊断方式，彻底解决了离线环境下证据链不完整和结论可靠性低的问题。

凭借场景化诊断脚本和标准化报告输出，该技能能够在离线环境中快速定位CPU故障的根本原因，为硬件更换提供精确指导，大幅缩短故障恢复时间，为企业服务器的稳定运行提供了强有力的技术保障。

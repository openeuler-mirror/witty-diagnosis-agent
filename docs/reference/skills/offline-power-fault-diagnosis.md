# 背景：服务器电源故障已成为运维工作的“痛点”

服务器电源系统是IT基础设施的核心保障，任何电源故障都可能导致业务中断、数据丢失甚至硬件损坏。随着服务器规模的不断扩大和密度的持续提升，电源故障的影响范围和排查难度也随之增加。传统电源故障排查方式依赖运维人员手动分析iBMC日志、OS系统日志和InfoCollect数据，需要深入理解电源架构、冗余机制和硬件信号传导链，技术门槛高且效率低下。快速定位电源故障根因的能力直接关系到服务器的稳定性和业务连续性。

# 问题与挑战：电源故障排查的三大核心困境

1. **硬件厂商多样性带来的日志格式差异**
   不同服务器厂商（华为、H3C、浪潮等）的iBMC日志格式、PSU状态编码、传感器命名规范各不相同。这种厂商差异导致通用分析脚本需要兼容多种日志格式，增加了开发和维护难度。

2. **日志完整性与可靠性风险**
   在电源故障发生瞬间，部分日志可能未能完整记录或被截断。特别是当PSU突然失效时，iBMC可能无法及时写入完整的故障信息。此外，日志文件可能因存储问题导致部分内容丢失，影响证据链的完整性。

3. **环境因素与硬件故障的耦合性**
   电源故障往往与环境因素紧密相关：机房温度异常可能导致PSU过热保护，供电质量问题可能引发电源误告警。环境因素与硬件故障的耦合增加了根因判定的复杂性，需要综合分析温度传感器数据、供电监测记录等多维度信息。

# 智能诊断Agent的解决方案：电源故障诊断的核心能力

面对上述挑战，Witty智能诊断Agent提供了专业的电源故障诊断解决方案：

* **多厂商日志格式兼容**：提供华为、H3C、浪潮三大主流厂商的iBMC分析指南，采用正则表达式进行模糊匹配，提高对不同厂商日志格式的兼容性。

* **证据矩阵校验机制**：建立时序连续性（E1）、物理同一性（E2）、现象排他性（E3）三维校验矩阵，通过交叉质询确保结论的可靠性。实现断链阻断和降级处分机制，避免结论发散，有效应对日志完整性风险。

* **环境因素综合分析**：专门检测温度相关事件（`temperature high`、`thermal fail`），建立温度-风扇-电源故障的传导链分析模型，有效区分环境因素与硬件故障的耦合影响。

* **场景化诊断与物理级精确定位**：基于故障特征自动分类六大场景（服务器掉电、电源模块故障、电压异常、电源冗余失效、电源过载、电源过热），并通过多维证据交叉验证，精确定位到具体的PSU槽位和故障组件。

# 使用流程

## 前置要求

### 日志准备要求
- 准备完整的服务器日志收集包，建议包含以下三类日志：
  - iBMC日志（ibmc_logs/）：包含SEL事件日志、传感器数据、PSU状态信息
  - OS消息日志（messages/）：包含dmesg、syslog、messages等系统日志
  - InfoCollect日志（infocollect_logs/）：包含功耗数据、电压采集、热状态信息

### 时间信息准备
- 若已知故障发生时间，建议记录具体的时间窗口，以便精准分析
- 若已知故障现象，建议准备相关关键词（如"power loss"、"PSU fault"等）

## 操作步骤

- 启动 **OpenCode**。

- 执行`/agents`命令选择`Xuanyuan`Agent。
  
- 输入故障问题描述，并**提供日志目录路径**，示例如下：
  
  ```shell
  服务器意外掉电，请分析位于/tmp/logs目录下的日志，定位故障根因并给出修复建议。
  ```

- 系统将自动执行**智能诊断**流程，包括日志采集、场景分类、深入分析和根因校验

- 诊断完成后，查看完整的诊断分析报告，报告包含故障摘要、故障时间链、故障传播链、技术分析与根因、修复建议。

# 总结

服务器电源故障涉及硬件、固件和环境多个维度的复杂交互，从外部供电到内部组件的任何环节异常都可能引发连锁反应。传统排查方式依赖运维人员的经验和专业知识，不仅效率低下，还容易被表面现象误导。

Witty智能诊断Agent通过**多厂商日志格式兼容**、**证据矩阵校验**和**环境因素综合分析**等核心能力，实现了电源故障的精准诊断。基于多维证据交叉验证的分析方式，能够有效应对日志完整性风险和环境因素干扰，精准定位到具体的PSU槽位和故障组件，为服务器的稳定运行提供可靠的技术支撑。

# Xuanyuan 测试输入标准

## 概述

本文档定义使用 OpenCode `Xuanyuan` Agent 验证诊断能力时的统一输入标准。正式测试应模拟真实用户反馈，让 Agent 基于故障现象和必要证据边界完成诊断，而不是把测试答案或诊断路线写进输入。

该标准适用于手动测试和自动化端到端测试。

## 输入原则

正式测试输入应满足以下原则：

1. 使用真实用户反馈式表达，只描述用户能够自然提供的故障现象。
2. 进程类问题优先只提供 PID 或进程名，例如进程内存持续上升、CPU 异常升高或进程卡住。
3. 服务、容器或主机类问题可以提供服务名、容器名、主机名或可访问的证据目录。
4. 当诊断实现需要结合业务日志分析时，可以提供应用路径，避免 Agent 无边界搜索。
5. 明确诊断阶段保持只读；修复、删除、重启、配置写入等操作必须另行确认。

## 推荐输入形式

进程类问题：

```text
PID 12345 对应的进程内存一直在上升，帮我分析下根因。
```

```text
python-worker 进程内存持续上涨，帮我定位原因。
```

服务类问题：

```text
nginx 服务最近频繁异常退出，帮我分析根因。
```

容器类问题：

```text
容器 app-backend 的 CPU 使用率持续偏高，帮我分析原因。
```

需要结合业务日志的问题：

```text
payment-service 进程内存一直在上升，应用路径是 /opt/payment-service，帮我分析根因。
```

## 禁止写入正式输入的信息

以下信息可以用于测试准备、评分、归档和 PR 说明，但不得写入正式的 Xuanyuan 测试输入：

- 目标 skill 名称或 skill 路径。
- 测试场景名称。
- 故障注入脚本或复现命令。
- 具体日志文件路径。
- 关键日志行、错误码解释或人工提取的证据摘要。
- 根因关键词、修复方向或预期结论。
- 评分标准、ground truth 或测试断言。

## 测试记录要求

测试记录或 PR 说明应区分正式输入和测试辅助信息：

- 正式输入：记录实际发送给 `Xuanyuan` Agent 的用户反馈式问题。
- 测试准备：记录故障注入、环境准备、证据生成和清理方式。
- 验证结论：记录报告是否命中预期根因、是否生成 Markdown/HTML 报告以及未验证项。

如果某个场景无法仅通过 PID、进程名、服务名或应用路径完成有效诊断，应在测试记录中说明原因，并列出实际补充的信息边界。

# 希捷 SM2 / FARM 日志底层诊断指南

在离线磁盘故障诊断的基础流程中，当我们通过日志（iBMC, InfoCollect, OS messages等）定位到疑似故障的磁盘时，如果该磁盘提供了更深层次的 **SM2 / FARM 级遥测日志**，我们就可以执行进一步的底层诊断，将故障收敛到具体的磁头、盘面或读写通道等核心部件。

## 适用场景判断 (触发条件)

本指南对应 SKILL.md **Step 5（SM2/FARM 底层深度诊断）**，满足以下**全部条件**时方可触发：

1. **前置条件（必须满足）**：已完成 Step 0–4，且前置步骤已识别出**某块特定物理磁盘**存在问题。
2. **数据条件（必须满足）**：当前分析数据集中存在对应的 `sm2_log` 目录，其中包含以磁盘 SN（序列号）为前缀的底层日志文件：
   - `<SN>_SMART_<时间戳>_SLog.txt`（整盘级）
   - `<SN>_SMART_<时间戳>_head0.txt`、`..._head1.txt` … `..._headN.txt`（逐磁头级）

> [!IMPORTANT]
> **触发前必须同时满足上述两个条件。** 若前置条件（Step 0–4 已有问题磁盘定位）不满足，即使存在 sm2_log 目录，也不应单独触发本步骤。

## 8 类故障部位 (分析框架)

对照标准 SMART，SM2 对各故障类别的覆盖度（详见 `references/sm2_field_reference.md` 第 3 章映射表）：

| # | 故障部位 | SM2 覆盖度 | 关键分析字段 |
|---|---|---|---|
| 1 | 盘片表面 / 坏扇区 | ✅ 优于标准（逐磁头） | `g_list` / `vis_rd_err` / `arre` |
| 2 | 磁头 / 读写通道 / ECC | ✅ 远优于标准 | `FAFH`（飞高） / `iter`（译码迭代） / `amp`（信号幅度） / `MRR`（电阻） |
| 3 | 机械 / 马达 / 伺服 | ⚠️ 部分覆盖 | `motor_power` / `servo_swd_*` / `oc_limit*`（无 spin-up/retry/LUL） |
| 4 | 接口 / 传输 | ⚠️ 部分覆盖 | `command_timeout` / `reset`（SAS 接口无 UDMA CRC） |
| 5 | 温度 / 环境 / 振动 | ✅ 优于标准 | `temperature` / `rv` / `humidity`（含湿度） |
| 6 | 寿命 / 工况 | ✅ 相当 | `poh` / 读写数据量 |
| 7 | 固件 / 服务区 | ⚠️ 部分覆盖 | `g_list` 规模 / `188` × `g_list` 联动（无离散 SA / assert 事件） |
| 8 | SSD 磨损 | ❌ 不适用 | HDD 机械硬盘不适用 |

## 专家判读方法论 (判断逻辑 · 依据 · 流程)

有经验的硬盘失效分析工程师面对 SM2 日志时的思考方式。**先理解这套逻辑，再去跑脚本**——脚本是这套方法论的自动化，但遇到边界形态、需要解释"为什么"或对外提供结论依据时，靠的是这套物理因果推理。

### A. 判断逻辑 (怎么想)

专家不是单纯地"逐个字段查阈值"，而是按五个步骤进行收敛：**部位 → 机理 → 严重度 → 趋势 → 决策**。

1. **先定部位，再谈数值**：任何异常先归到 8 类故障部位之一。同样是"读错误多"，落在"盘片坏扇区"还是"接口超时"上，处置完全不同（换盘 vs 更换线缆/背板）。
2. **用机理串因果，而不是堆砌指标**：真正可信的结论是一条**物理因果链**。
   > HDD 最典型的退化链：
   > 盘面/磁头介质退化 → 飞高 (FAFH) 偏移、信号裕量下降 → 译码迭代 (iter) 升高、信号幅度 (amp) 下降 → 读错误 (hid/vis) → 坏扇区重映射 (g_list ↑) → 命令超时 (188) → SCSI I/O 错误 → 操作系统文件系统只读/宕机。
   
   能把观察到的字段对号入座到这条链的某几环，结论才立得住。
3. **种群相对法 > 绝对阈值**：同一块盘的 $N$ 个磁头同工艺、同负载、同环境，是天然的对照组。
   "全家就它一个不一样"的离群磁头，比任何手册阈值都更加灵敏可靠——这是 SM2 逐头数据最大的分析价值。`FAFH` / `iter` 关注谁明显偏高，`amp` 关注谁明显偏低。
4. **严重度分级看"是否已伤到数据面"**：`hid_rd_err`（盘内部已恢复）是预警；`vis_rd_err`（不可恢复、已上抛主机）是已经伤到业务的硬证据；`g_list` > 0 说明已在动用备用扇区。
   > **分级定义**：关注（内部可恢复） < 退化（已上抛/缺陷增长） < 失效（磁头开路/固件死锁）。
5. **趋势决定生死，而非静态快照**：同一个 `g_list` = 1100，"很久前涨上来、近期不再变动"（暂稳）和"持续增长"（活跃）的处置策略截然相反。
   因此**必须看旧 → 新的发展方向**。单调累计计数器（`g_list`、`command_timeout`）若出现"下降"，几乎一定是时间方向读反。

### B. 判断依据 (凭什么)

- **现场统计规律**：统计显示，76.7% 的故障盘在失效前 SMART 5/187/188/197/198 至少一项非零；单项非零时故障概率约为 30%–40%，而**第 1 类（`g_list` / 坏扇区）与第 2 类（不可恢复读）同时非零并持续增长时，故障概率升至约 76%**——所以分析重在组合与共振，不轻信单项指标。
- **计数器语义**：`g_list`（增长缺陷表）与 `command_timeout` 是**单调累计量**，正常情况下只增不减；重映射坏扇区是往 `g_list` 里"增加"记录。此语义既用来定方向，也用来证伪"自愈下降"的错误解读。
- **物理量含义**：`FAFH` = 飞高间隙、`iter` = LDPC 译码努力、`amp` = 回读信号幅度、`MRR` = 磁阻磁头电阻、`oc_limit` = 执行器过流限制——它们直接对应磁头 / 盘面 / 伺服的物理状态，比标准 SMART 的私有 Raw 值更接近"物理本质"。
- **跨层佐证**：SM2 只能证明"盘体哪个部位退化"；要断定"造成了业务故障"，需要主机内核日志（`Medium Error` → `XFS shutdown`）对齐时间与设备，形成"盘体证据 + 系统证据"的闭环。此跨层佐证与 SKILL.md Step 4 的根因校验相互补充——Step 4 从系统侧向下溯源，SM2 从盘体侧向上印证。
- **覆盖度自知**：第 3/4/7 类只是部分覆盖，第 8 类不适用——结论中应当明确标注"此类看不全"，不强行猜测下结论。

### C. 分析流程概要 (怎么走)

```
①归集分组：按 SN 把一台服务器的文件分成多块盘
②时间校正：按 poh 升序，确认 record0=最新，趋势一律旧→新（运行脚本前必须了解，脚本已自动处理）
③逐头体检：每块盘 N 个磁头横向互比，挑出离群头（种群相对法）
④八类归位：把每项异常落到 8 类故障部位，标注覆盖度
⑤机理串链：用物理因果链把字段串成一句"哪里坏了、怎么坏的"
⑥分级研判：按"是否伤到数据面 + 活跃/暂稳"定严重度
⑦机群排序：多盘按健康度差→好排队，定处置优先级
⑧跨层佐证：必要时与 Step 0–3 中已收集的主机日志对齐，闭环到业务影响
⑨给出处置：换盘 / 磁头级降级 / 换线缆 / 改环境 / 带外重启 + 留用退出条件
```
脚本已自动执行 ①②③–⑦ 并给出建议；判读人重点复核 ⑤（因果链是否成立）、⑧（是否需要与主机日志交叉印证）与 ⑨（处置是否匹配现场）。

## Step 5 工作流 (对应 SKILL.md Step 5.1 → Step 5.2)

> [!IMPORTANT]
> **时间方向须知（运行脚本前必须了解）**
> 记录按 `poh` 排序，`poh` 最大 = 最新快照。多数导出日志为时间倒序（即 record 0 = 最新）。
> **趋势必须按 旧 → 新 方向解读**。否则会把 "`g_list` 0 → 1100 持续增长（在恶化）" 误读为 "1100 → 0 下降（自愈）"，导致健康结论彻底相反！
> **自检方法**：`g_list` 与 `command_timeout` 是单调累计计数器，正常只增不减。若解读中出现"下降"，一定是时间方向读反了。脚本已自动按 `poh` 升序计算，输出 `方向: grow/shrink/flat` 即代表旧 → 新。

### Step 5.1：运行分析脚本 (对应 SKILL.md § 5.1)

脚本封装了全部分析逻辑：多盘发现 → 按 `poh` 升序时间排序 → 逐头聚合 → 8 类判定 → 故障分类 → 机群报告，每次运行结果一致。

```bash
# 运行分析脚本（支持单盘或多盘目录）
python3 scripts/analyze_sm2.py <sm2_log_dir>

# 运行分析脚本并输出 JSON 格式
python3 scripts/analyze_sm2.py <sm2_log_dir> --json
```

脚本会直接输出：**机群汇总表**（按健康度 差 → 好 排序） + 每块盘的**逐类（8 类）分析表** + **逐磁头明细表** + **结论与处置建议**。

### Step 5.2：对照参考进行专业判读 (对应 SKILL.md § 5.2)

脚本给出结论，而 `references/sm2_field_reference.md` 提供详细判定依据。当需要解释"为什么这么判"、查询某个具体字段的物理含义、确认临界阈值、查看 8 类与字段映射，或遇到脚本未覆盖的特殊边界形态时，请查阅该参考文件。

**判读核心方法**：

1. **种群相对法（首要方法）**：同一块盘的 $N$ 个磁头处于相同工艺、负载和环境，横向互比更容易挑出离群磁头（`FAFH` / `iter` 取高离群，`amp` 取低离群）。
2. **趋势判断（活跃 vs 暂稳）**：确认 `g_list` 和 `vis_rd_err` 等核心报错是活跃增长状态（需立即处置）还是暂稳（可留用监控）。
3. **组合判读**：单项 Raw 值 > 0 时故障概率约 30%–40%；第 1 类（`g_list` / `vis_rd_err`） + 第 2 类（不可恢复读）同时非零且持续增长时，故障概率升至约 76%——属于最优先级换盘。
4. **常量忽略**：`OTFErr` = 26728 (`0x6868`) 是希捷固件定义的固定常量，非故障，直接忽略。
5. **健康判定与处置**：按 `references/sm2_field_reference.md` 第 6 章的判定矩阵逐盘归类（健康 / 亚健康 / 单磁头退化 / 多磁头退化 / 某类别异常 / 固件死锁），区分活跃退化与暂稳状态。多盘场景下，根据机群汇总表的"差 → 好"排序分配处置优先级。详细处理方法见 `references/sm2_field_reference.md` 第 8 章。

**与主机日志交叉印证（如需）**：

SM2 数据仅反映磁盘内部的物理及遥测指标。若需要将磁头退化与上层业务影响闭环，需结合已在 Step 0–3 中收集的主机 `dmesg` / `/var/log/messages`（关键词如 `Medium Error`、`xfs_do_force_shutdown` 等），对齐时间戳与设备标识（详见 `references/sm2_field_reference.md` 第 9 章）。此步骤为 Step 5 的**可选增强**，其结论将直接支撑 Step 6 报告中的"故障传播链"描述。

## 核心纪律 (一句话速记)

- **触发前提**：必须已完成 Step 0–4 并识别出问题磁盘，且存在 `sm2_log` 数据，方可触发 Step 5。
- **时间方向**：`poh` 大为新，必须按**旧 → 新**读取趋势，否则结论完全相反。
- **种群相对**：同盘磁头横向互比寻找离群磁头，比绝对阈值更灵敏。
- **整盘 SMART 会说谎**：整盘级的 `g_list` 可能恒为 0，而单磁头的退化只在逐磁头数据中可见。
- **覆盖度要诚实**：第 3/4/7 类为部分覆盖，第 8 类 (SSD) 对 HDD 不适用，结论中必须明确说明。
- **结论边界**：SM2 仅能证明磁盘内部物理及通道的退化，对业务的具体影响需结合主机操作系统日志（如 SCSI Error / XFS 报错）进行闭环佐证。
- **禁止独立成文**：Step 5 结论必须并入 Step 6 最终报告，**严禁**生成独立的 SM2 报告文件。

## 1. 日志是什么 / 多盘结构

**FARM = Field-Accessible Reliability Metrics**，希捷专有“现场可读可靠性指标”，比标准 SMART（CrystalDiskInfo 约 30 项）详细得多。
本类 **SM2** 是更详尽的工厂变体，关键差异是**把指标拆到每个磁头**单独成文件。

**单盘** = 一组同序列号（SN）的文件：
| 文件 | 数量 | 内容说明 |
|---|---|---|
| `<SN>_SMART_<ts>_SLog.txt` | 1 | 整盘级（电压/温度/振动/超时/马达/缺陷表… 约 100 列） |
| `<SN>_SMART_<ts>_head{0..N}.txt` | $N$ | 逐磁头（飞高/磁阻/读错误/译码迭代/伺服… 约 48 列） |

**多盘 (一台服务器)**：把多块盘的文件放在一个父目录（可有子目录）。脚本**递归扫描、按文件名 SN 前缀分组**成多块盘，逐盘分析后给出**机群汇总表**（按健康度差 → 好排序）。每个文件是 CSV 时间序列（常见 1000 条记录，首行表头）。

**机型识别**：18 磁头 + 双致动器 = **Mach.2（如 Exos 2X18 / ST20000NM002H）**，`H0`–`H8` 属于致动器 0，`H9`–`H17` 属于致动器 1。

## 2. 时间方向纪律 (最易错)

记录用 `poh`（power-on 累计上电时间）排定时间，**注意：不是自然日历时间**。**`poh` 最大值 = 最新快照**。
许多工具导出的日志是**倒序**的（即 record 0 = 最新记录）。

> [!WARNING]
> **必须按 旧 → 新 方向解读趋势！**
> 否则会把 “`g_list` 0 → 1100 持续增长（在恶化）” 误判为 “1100 → 0 下降（自愈）”，导致健康结论彻底相反。真实事故报告中曾出现过该类严重误判。
> 
> **自检规则**：`g_list` 与 `command_timeout` 为单调累计计数器，正常情况下只增不减。如果你得出的结论中出现了它们“下降”，几乎可以肯定时间方向读反了。脚本已统一按 `poh` 升序排序计算，输出的 `方向: grow/shrink/flat` 即代表旧 → 新趋势。

## 3. 八类故障部位 ↔ SM2 字段映射 (能不能分析)

按“故障部位 + 失效机理”对照标准 SMART，列出 SM2 实际可用字段与覆盖度。
**覆盖度**：✅ 可分析（≥ 标准 SMART） / ⚠️ 部分可分析 / ❌ 不适用。

| # | 故障部位 | 标准 SMART 字段 | SM2 可用字段 | 覆盖度 |
|---|---|---|---|---|
| 1 | **盘片表面 / 坏扇区** | `5`, `196`, `197`, `198` | 逐头 `g_list`（增长缺陷表 ≈ 重分配）、`vis_rd_err`（不可恢复读 ≈ `198`）、`arre`（自动重分配读事件）、`initial_rd_err`；盘级 `g_list`、`rsvd_zone_scan_count` | ✅ 优于标准（逐头） |
| 2 | **磁头 / 读写通道 / ECC** | `1`, `7`, `187`, `189`, `195` | 逐头 `hid_rd_err` / `vis_rd_err` / `initial_rd_err`（≈ `187`/`1`）、`iterOD/MD/ID`（LDPC 译码迭代 ≈ ECC 努力 / `195`）、`ampOD/MD/ID`（读信号幅度）、`fafh_*`（飞高 / TFC ≈ `189` 高飞写）、`head_resistance` / `mr2_head_resistance`（MRR 磁头电阻，标准 SMART 无）、`bad_sample`、`berp_rec_error`、`asymRead`、`bieOD/MD/ID` | ✅ 远优于标准（逐头逐区） |
| 3 | **机械 / 马达 / 伺服** | `3`, `4`, `10`, `192`, `193` | 盘级 `motor_power`（主轴功率）、`power_cycle_cnt`；逐头 `servo_swd_*`、`vel_no_tmd` / `vel_obs`、`oc_limit4/9/14`（执行器过流限幅） | ⚠️ 部分（无 spin-up time / spin-retry / load-unload 计数） |
| 4 | **接口 / 传输 / 线缆** | `188`, `199` | 盘级 `command_timeout_9`（≈ `188`）、`host_reset`、`hard_reset` | ⚠️ 部分（SAS 盘无 UDMA CRC 项） |
| 5 | **温度 / 环境 / 振动** | `190`, `191`, `194` | 盘级 `temperature` / `_min` / `_max`、`rv` / `rv_max`（旋转振动）、`lv_Shock`、`humidity` / `_min` / `_max`（湿度，标准 SMART 无） | ✅ 优于标准（含湿度） |
| 6 | **寿命 / 工况** | `9`, `12`, `240`, `241`, `242` | 盘级 `poh`、`power_cycle_cnt`、`read_cmd_*` / `write_cmd_*`、`idle_*`；逐头 `sector_rd` / `sector_wt` | ✅ |
| 7 | **固件 / 服务区 / 内部** | 深度日志核心 | `g_list` 规模、`rsvd_zone_scan_count`、`bms_smart_unlock_status`、`flag_wsv4` / `flags1`、`trigger_capture`、`fw_activity_idle_time`；**`command_timeout` × `g_list` 联动**（`188` 深层常指向服务区 / 转换表） | ⚠️ 部分（无离散 SA / translator / 固件 assert 事件记录，需原厂工具解析深度事件日志） |
| 8 | **SSD 特有** | 磨损 / PE / TBW | — | ❌ 不适用（本类为机械盘：有磁头 / 飞高 / 主轴） |

**一句话总结**：SM2 把第 1/2/5/6 类做到**优于或等于**标准 SMART（且逐头），第 3/4/7 类**部分**覆盖，第 8 类对 HDD 不适用。
SM2 还**额外**提供标准 SMART 没有的维度：逐头 MRR 电阻、逐区飞高/TFC、译码迭代、信号幅度、伺服/执行器过流、湿度。

## 4. 关键字段字典

### 4.1 整盘级 (SLog)
| 字段 | 含义 | 判读重点 |
|---|---|---|
| `serial_number` / `firmware` / `head_cnt` / `sector_size` | 身份与配置 | 18 头代表 Mach.2 双致动器硬盘 |
| `poh` | 累计上电计数（Power-on Hours） | 仅用于时间排序与时间线对齐 |
| `temperature`（`_min` / `_max`） | 温度（℃） | 过温容易诱发磁盘读写不稳或损坏 |
| `volt_5` / `volt_12` | 5V / 12V 供电电压 | 电压超出允许范围会引发硬件级不稳 |
| `rv` / `rv_max`、`lv_Shock` | 旋转振动（RV） / 冲击 | 高振动会导致磁头寻道抖动、效能下降 |
| `humidity`（`_min` / `_max`） | 湿度 | 衡量物理运作环境（标准 SMART 无此项） |
| `command_timeout_9` | SCSI 命令超时累计（≈ `188`） | **关键指标**：旧 → 新持续增长代表磁盘超时，将引起上层 SCSI 报错 |
| `host_reset` / `hard_reset` | 主机复位 / 硬件复位 | 链路及接口异常的侧面旁证 |
| `motor_power` | 主轴马达功率 | 机械磨损及轴承阻力的侧面旁证 |
| `rsvd_zone_scan_count` | 保留区（服务区）扫描次数 | 服务区或内部缺陷管理活动的频率 |
| `g_list` | 整盘增长缺陷表 | **特别注意**：整盘级 `g_list` 可能恒为 0，而退化可能仅在逐头数据中可见（标准 smartctl 极易漏判） |

### 4.2 逐磁头级 (headN) —— 健康判定主战场
| 字段 | 含义 | 判读重点 |
|---|---|---|
| `g_list` | 该磁头增长缺陷表（已重映射坏扇区累计） | **核心指标**：> 0 即代表存在物理介质缺陷；旧 → 新持续增长说明退化正活跃；重映射只会增加不会减少 |
| `vis_rd_err` | 可见 / 不可恢复读错误（已上抛主机） | **核心指标**：正常状态下应恒为 0；> 0 表示物理坏道已影响到业务层 |
| `hid_rd_err` / `initial_rd_err` | 内部已恢复 / 首次读错误 | 相对同盘其它磁头偏高，是信号裕量下降的早期预警信号 |
| `fafh_passclr_od/md/id`、`fafh_applied_*` | 飞高/TFC 间隙（OD/MD/ID = 外/中/内圈） | **核心指标**：某磁头显著高于其它磁头说明物理特性发生偏移；FAFH 瞬态为 0 表明 TFC 控制中断 |
| `iterOD/MD/ID` | LDPC 译码迭代次数 | **核心指标**：某头迭代次数显著高于其它磁头，说明低 SNR 下解码吃力（读通道劣化） |
| `ampOD/MD/ID` | 回读信号幅度 | 某磁头幅度偏低代表信号较弱 |
| `head_resistance` (MRR1) / `mr2_head_resistance` (MRR2) | 磁阻读头电阻 | `0xFFFF` 代表磁头开路或饱和（损坏）；阻值明显偏离种群中位数则为边缘磁头 |
| `arre` | 自动重分配读事件数 | 代表该磁头重映射动作的频繁程度 |
| `oc_limit4/9/14`、`servo_swd_*`、`vel_*` | 执行器过流限幅 / 伺服状态 / 速度指标 | 非零或偏离同族代表寻道、伺服或执行器控制面临异常压力 |
| `sector_rd` / `sector_wt` | 该磁头读写扇区量 | 该磁头的工作负载，用于横向对比 |
| `bad_sample`、`berp_rec_error`、`*_scrubs`、`bg_*` | 坏采样 / 纠错恢复 / 后台巡检等 | 辅助佐证磁盘退化的活跃程度 |
| `OTFErr` | On-The-Fly 实时错误 | **特别注意**：本类硬盘中恒为 26728 (`0x6868`)，是固件常量，非故障，请直接忽略 |

> [!NOTE]
> **判读心法 —— 种群相对法**
> 同一块盘的 $N$ 个磁头处于相同工艺、负载和环境，**横向互比**寻找离群磁头，比绝对阈值更灵敏。脚本对 `fafh`、`iter`（取高离群）与 `amp`（取低离群）做中位数 × 比例的离群判定。

## 5. 临界值表

| 指标 | 正常范围 | 关注阈值 | 异常 / 临界阈值 |
|---|---|---|---|
| 温度 | < 50℃ | ≥ 60℃ | ≥ 70℃ |
| 5V / 12V 电压 | 4.75V – 5.25V / 11.40V – 12.60V | 接近电压上下限边界 | 超出限制范围 |
| `rv_max` | 较低 | ≥ 40 | ≥ 80 |
| 湿度 | 正常 | ≥ 80% | — |
| `command_timeout` | 0 且无增长趋势 | 出现少量超时记录 | 旧 → 新持续增长 |
| 逐头 `g_list` | 0 | 出现缺陷但保持稳定或下降 | **> 0 且旧 → 新增长**，或累计绝对值达数百至数千 |
| 逐头 `vis_rd_err` | 0 | — | **任意 > 0** |
| 逐头 `hid_rd_err` | 0 或极低 | 相对同盘其它磁头偏高 | 持续增长 |
| 逐头 `FAFH` 均值 | 处于同族中位数 ±20% 范围内 | 超出中位数 1.2 倍 | 远超中位数 / 频繁出现 0 / 达到标记值 |
| 逐头 `iter` 译码迭代 | 处于同族中位数附近 | 超出中位数 1.2 倍 | 显著高于同盘其它磁头 |
| 逐头 `amp` 信号幅度 | 处于同族中位数附近 | 低于中位数 0.8 倍 | 显著低于同盘其它磁头 |
| `head_resistance`（MRR） | 处于同盘其它磁头的正常区间 | 偏离正常范围 | `= 0xFFFF`（磁头开路） |
| `oc_limit*` 执行器过流 | 0 | 个别磁头非零 | 多个磁头非零或严重偏离阻值 |

> [!NOTE]
> 阈值集中定义在 `scripts/analyze_sm2.py` 顶部（如 `TEMP_*`、`V*_*`、`RV_*`、`OUTLIER_HI/LO` 等），针对不同机型分析时可按需微调。

## 6. 健康判定矩阵与故障模式

根据“受影响磁头数 × 趋势状态 × 接口/TFC 异常 × 最高严重度”进行整盘归类：

| 故障模式 | 物理与遥测特征 | 最终判定 | 延寿可行性评估 |
|---|---|---|---|
| **健康** | 所有磁头 `g_list` = 0、读错误 = 0，`FAFH` / `iter` 均匀且无偏离，运行环境指标正常 | 健康 | — |
| **轻度异常 / 早期预警** | 个别磁头或单项分类达到“关注”级别，无物理失效磁头 | 亚健康 | **高**（维持监控即可） |
| **单磁头退化** | 仅有 1 个磁头表面或读写通道出现异常，其余磁头指标健康 | 退化（视趋势分活跃/暂稳） | **活跃状态**：可行性低，建议降级或换盘；<br>**暂稳状态**：可行性高，可在中期留用监控 |
| **多磁头介质退化** | 存在 2 个及以上的磁头退化 | 严重退化 | **中等偏低**，建议尽快备份数据并换盘 |
| **某类别异常** | 无具体磁头失效，但盘级某项分类（如接口、环境）达“退化”级 | 严重异常 | 根据故障类别进行特定处置（如改善环境、换线） |
| **固件死锁 / 多头 TFC 失效** | 多个磁头的 `FAFH` 恒为 0 或显示标记值，伴随 `command_timeout` 大量增长 | 失效 | **低**，应优先带外重启并换盘 |

> [!NOTE]
> **“活跃 vs 暂稳”判据 (针对单磁头退化判定最为关键)**
> 满足以下任意条件即归为**活跃退化**，否则为**暂稳**状态：
> - `g_list` 在旧 → 新趋势中出现增长
> - `g_list` 最新记录值 > 0
> - 出现新的 `vis_rd_err`
> - `command_timeout` 在旧 → 新趋势中出现增长
> 
> 处于活跃退化状态的磁盘不能轻易留用；暂稳状态的磁盘可在 RAID 冗余保护下进行中期观察。

> [!IMPORTANT]
> **指标组合研判原则**
> 单一指标异常（如单一 Raw > 0）时故障概率约 30%–40%；而**第 1 类（`g_list` / `vis_rd_err`）与第 2 类（`187` 类不可恢复读）同时非零且持续增长**时，设备失效概率升至约 76%——这是最应该优先安排数据备份和换盘的故障组合。

## 7. 标记值 / 常量

| 十六进制 | 十进制 | 含义与判读建议 |
|---|---|---|
| `0xFFFF` | 65535 | 满量程/溢出，通常代表磁头开路或传感器饱和（确定发生硬件故障） |
| `0xDEAD` | 57005 | 固件标志值，代表“未校准 / 无效数据” |
| `0x6868` | 26728 | 希捷固件中 `OTFErr` 对应的固定常量，**非故障，请直接忽略** |

## 8. 处理方法

- **健康 / 亚健康**：进行常规或周期性监控。重点监控逐磁头 `g_list` 的增长速率、`FAFH` / `iter` 趋势。由于整盘级 `g_list` 常显示为 0，单磁头退化在此类状态下仅能通过逐头遥测感知。
- **单磁头退化 (活跃)**：确认 RAID 组冗余状态 → 优先尝试**磁头级降级**（通过希捷专有工具屏蔽故障磁头，整盘容量减少约 $1/磁头数$） → 若无专用工具则安排**换盘**。若该盘已导致文件系统只读或损坏，优先运行 `xfs_repair` 再重新挂载。
- **单磁头退化 (暂稳)**：在 RAID 冗余保护下中期留用，并加强监控频率。**触发退出的硬条件（满足任一须立即换盘或降级）**：故障磁头 `g_list` 再次增长；出现新的 `vis_rd_err` 或 `hid_rd_err`；`FAFH` / `iter` 持续恶化；`command_timeout` 再次增加；RAID 组内其它磁盘出现 Predicted Failure。
- **多磁头介质退化**：立刻抢救数据 → 运行 `xfs_repair` 修复文件系统 → 评估降级可行性，通常建议尽快换盘。
- **接口 / 传输类异常**：优先排查连接线缆、背板或 HBA 卡（如 SAS 接口重新插拔、更换槽位）。若伴随有 `g_list` 增长，则需按固件/服务区故障逻辑对待。
- **温度 / 振动类异常**：改善机柜散热、优化减震措施后重新测试，这通常不是盘体本身的物理坏道。
- **固件死锁 / 多头 TFC 失效**：此时磁盘在操作系统内通常已无响应，尝试带内修复多无效果，应通过 IPMI/带外管理进行电源重启，恢复后执行数据备份并更换硬盘，同时排查是否需升级固件。
- **机群级处置优先级**：按照“机群汇总表”中“差 → 好”的顺序依次处理，优先处置“失效”与“退化”级硬盘。同一级别下，优先处置退化活跃度高、受影响磁头数多的磁盘。

## 9. 与主机日志联动

SM2 是磁盘内部的硬件遥测指标，并不包含文件系统或具体上层业务的影响。当需要诊断上层 I/O 错误或挂载卷挂死时，必须联动操作系统内核日志：

- **主机日志关键词**（`dmesg` / `/var/log/messages`）：`Medium Error`、`Unrecovered read error`、`critical medium error`、`I/O error, dev sdX`、`command timed out`、`XFS ... metadata I/O error`、`xfs_do_force_shutdown`、`Shutting down filesystem`。
- **典型链路传导**：`某磁头介质/飞高退化（SM2 定位到具体 headN）` → `产生不可恢复读错误/命令超时` → `操作系统上抛 SCSI I/O 错误` → `XFS 文件系统元数据损坏` → `触发文件系统强制 shutdown（只读）`。
- **应急恢复**：仅 `umount` 并不能修复损坏的元数据，脏日志的存在也会导致 `mount` 重新挂载时被拒绝或依然处于只读状态。须在卸载状态下运行文件系统修复工具（如 `xfs_repair`）修复后，方可重新挂载读写（前提是磁盘仍能响应 SCSI 且仅有元数据层面的损坏）。

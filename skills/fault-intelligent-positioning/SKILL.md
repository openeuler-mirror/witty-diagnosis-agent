## 故障智能定位 (Fault Intelligent Positioning)

本 Skill 是故障智能定位的主控模块。当用户输入故障问题时，本 Skill 负责协调整个分析流程。

## 工作流程

1.  **明确时间上下文**:
    *   **确认当前时间**：首先明确当前的系统时间（Today's date）或用户提到的当前时间。
    *   **初步推断时间段**：根据用户描述推断故障发生的大致时间段（如“刚刚”推断为最近 30 分钟）。
    *   **“刚刚/最近”的判定原则**：当用户使用“刚刚”、“最近”等相对时间词时，必须**从最新的时间点向前回溯**。
        *   如果后续步骤发现日志中有多个异常时间点（例如 09:00 和 17:30 都有错误），而当前是 18:00（或日志最后时间是 18:00），**必须**优先分析 17:30 的问题。
        *   严禁因为早期的错误看起来更严重（如“Read-only file system”）就忽略了时间相关性。时间匹配度优先于错误严重度。
    *   **注意**：此时尚未下载日志和数据，不要尝试读取文件。具体的时间对齐和校准将在后续步骤（定界和根因定位）中通过检查实际数据来完成。
    *   **决策输出**：决定一个初步的“故障分析时间窗口”（Start Time 到 End Time），用于后续步骤的初始输入。

2.  **获取背景信息与数据准备**:
    *   调用 **`fault-background-info`** Skill。
    *   阅读该 Skill 提供的静态背景描述，理解当前场景的拓扑和关键指标。
    *   如果需要下载log，使用该 Skill 提供的 `log_fetcher.py` 工具下载日志。

3.  **故障定界**:
    *   调用 **`fault-delimitation`** Skill。
    *   使用其提供的分析工具来识别可疑组件和异常时间点。

4.  **根因定位**:
    *   调用 **`root-cause-localization`** Skill。
    *   基于定界结果和提供的分析工具，分析根本原因。

5.  **报告生成**:
    *   综合上述步骤的输出，向用户提供最终的分析结论。
    *   最终对用户可见的输出必须使用以下“最终输出格式要求”模板生成一份 Markdown 报告，仅输出该报告。
    *   报告结构请参考参考文档：[output_report_template.md](references/output_report_template.md)

### 最终输出格式要求（务必严格遵守）

在完成所有分析与评估决策后，你需要向用户输出一份面向业务方的最终诊断报告，使用 Markdown 格式。

**请务必阅读并严格遵守 [output_report_template.md](references/output_report_template.md) 中定义的报告结构和内容要求。**

无论是 OpenRCA、磁盘故障等任何场景，最终生成对用户可见的结果时，都必须按照上述参考文档中的 Markdown 结构组织内容。

## 交互示例

> 用户: "订单服务调用异常，帮我分析原因"

**执行逻辑**:
1.  确认当前时间，并根据用户描述（“订单服务调用异常”）推断应关注最近的时间段。
2.  查阅 `fault-background-info` 了解当前问题对应的服务架构、组件拓扑和关键指标等背景信息，并按需下载log。
3.  按需调用 `fault-delimitation` 分析指标异常。
4.  调用 `root-cause-localization` 分析日志根因。
5.  输出结论。

# 希捷 SM2 / FARM 日志磁盘健康分析(多盘 · 8 类故障部位)

通过希捷盘的 **SM2 / FARM 级内部遥测日志**,对**一块盘或一台服务器的多块盘**判定健康、
按 **8 类故障部位**定位问题、把故障收敛到**具体磁头/盘面**,并给出机群级处置与延寿建议。
这类日志比标准 SMART 细得多——它把可靠性指标**拆到每个磁头**,因此能发现
"整盘 SMART 看似正常、其实某个磁头已在退化"的隐性故障。

## 目录结构

```
├── scripts/

└── references/
    └── field_reference.md        # 8类↔字段映射 + 字段字典 + 临界值 + 判定矩阵 + 处理方法(判读细节看这里)
```

## 适用输入
一个目录,内含**单盘**或**一台服务器多盘**的 SM2 日志(可有子目录)。脚本按文件名 SN 前缀分组:
- 单盘 = 一组同 SN 文件:`<SN>_SMART_<ts>_SLog.txt` + `…_head0.txt … headN.txt`(18 个=Mach.2 双致动器盘)
- 多盘 = 多组不同 SN 的文件放同一父目录

每个文件是 CSV 时间序列(常见 1000 条记录,首行表头)。

## 8 类故障部位(本技能的分析框架)
对照标准 SMART,SM2 对各类的覆盖度(详见 `references/field_reference.md` 第 3 章映射表):

| # | 故障部位 | SM2 覆盖 |
|---|---|---|
| 1 | 盘片表面/坏扇区(g_list/vis_rd_err/arre) | ✅ 优于标准(逐头) |
| 2 | 磁头/读写通道/ECC(FAFH 飞高/iter 译码迭代/amp 幅度/MRR 电阻) | ✅ 远优于标准 |
| 3 | 机械/马达/伺服(motor_power/servo/oc_limit) | ⚠ 部分(无 spin-up/retry/LUL) |
| 4 | 接口/传输(command_timeout/reset) | ⚠ 部分(SAS 无 UDMA CRC) |
| 5 | 温度/环境/振动(temp/rv/humidity) | ✅ 优于标准(含湿度) |
| 6 | 寿命/工况(poh/读写量) | ✅ |
| 7 | 固件/服务区(g_list 规模/188×g_list 联动) | ⚠ 部分(无离散 SA/assert 事件) |
| 8 | SSD 磨损 | ❌ HDD 不适用 |

## 专家判读方法论(判断逻辑 · 依据 · 流程)

下面是一个有经验的硬盘失效分析工程师面对 SM2 日志时的思考方式。**先理解这套逻辑,再去跑脚本**——
脚本是这套方法论的自动化,但遇到边界形态、要解释"为什么"、或要对外背书结论时,靠的是这套推理而非死记阈值。

### A. 判断逻辑(怎么想)
专家不是"逐个字段查阈值",而是按五步收敛:**部位 → 机理 → 严重度 → 趋势 → 决策**。

1. **先定部位,再谈数值。** 任何异常先归到 8 类故障部位之一(盘片/磁头通道/机械/接口/环境/寿命/固件/SSD)。
   同样是"读错误多",落在"盘片坏扇区"还是"接口超时"上,处置完全不同(换盘 vs 换线缆)。
2. **用机理串因果,而不是堆指标。** 真正可信的结论是一条**物理因果链**,而不是"这几项数字高"。
   HDD 最典型的链:`盘面/磁头介质退化 → 飞高(FAFH)偏移、信号裕量下降 → 译码迭代(iter)升高、幅度(amp)下降
   → 读错误(hid/vis) → 坏扇区重映射(g_list↑) → 命令超时(188) → SCSI I/O 错误 → 文件系统宕机`。
   能把观察到的字段**对号入座到这条链的某几环**,结论才立得住。
3. **种群相对 > 绝对阈值。** 同一块盘的 N 个磁头同工艺、同负载、同环境,是天然的对照组。
   "全家就它一个不一样"的离群磁头,比任何手册阈值都灵敏可靠——这是 SM2 逐头数据最大的价值。
   FAFH/iter 看"谁明显偏高"、amp 看"谁明显偏低"。
4. **严重度分级看"是否已伤到数据面"。** `hid_rd_err`(盘内部已恢复)是预警;`vis_rd_err`(不可恢复、已上抛主机)
   是已经伤到业务的硬证据。`g_list`>0 说明已在动用备用扇区。分级:关注(内部可恢复)< 退化(已上抛/缺陷增长)< 失效(磁头开路/固件死锁)。
5. **趋势决定生死,而非快照。** 同一个 g_list=1100,"很久前涨上来、近期不再动"(暂稳)和"还在涨"(活跃)处置相反。
   所以**必须看 旧→新 的方向**;单调累计计数器(g_list、command_timeout)若"下降",几乎一定是时间读反。

### B. 判断依据(凭什么)
- **现场统计规律**:Backblaze 数万块盘的统计显示,76.7% 的故障盘在失效前 SMART 5/187/188/197/198 至少一项非零;
  单项非零故障概率约 30–40%,而**第1类(g_list/坏扇区)+第2类(不可恢复读)同时非零并增长时升至约 76%**——
  所以专家重组合、重共振,不轻信单项。
- **计数器语义**:`g_list`(增长缺陷表)、`command_timeout` 是**单调累计**量,正常只增不减;重映射坏扇区是往 g_list 里"加"。
  这条语义既用来定方向(见 A5),也用来证伪("自愈下降"的解读)。
- **物理量含义**:FAFH=飞高间隙、iter=LDPC 译码努力、amp=回读信号幅度、MRR=磁阻磁头电阻、oc_limit=执行器过流——
  它们直接对应磁头/盘面/伺服的物理状态,比标准 SMART 的私有 Raw 值更接近"机理真相"。
- **跨层佐证**:SM2 只证明"盘体哪个部位退化";要断定"造成了业务故障",需主机内核日志(Medium Error→XFS shutdown)对齐时间与设备,
  形成"盘体证据 + 系统证据"的闭环。
- **覆盖度自知**:第 3/4/7 类只是部分覆盖、第 8 类不适用——专家会明确说"这一类我看不全",而不是强行下结论。

### C. 大致流程(怎么走)
```
①归集分组：按 SN 把一台服务器的文件分成多块盘
②时间校正：按 poh 升序，确认 record0=最新，趋势一律旧→新
③逐头体检：每块盘 N 个磁头横向互比，挑出离群头（种群相对法）
④八类归位：把每项异常落到 8 类故障部位，标注覆盖度
⑤机理串链：用物理因果链把字段串成一句"哪里坏了、怎么坏的"
⑥分级研判：按"是否伤到数据面 + 活跃/暂稳"定严重度
⑦机群排序：多盘按健康度差→好排队，定处置优先级
⑧跨层佐证：必要时拉主机日志对齐，闭环到业务影响
⑨给出处置：换盘 / 磁头级降级 / 换线缆 / 改环境 / 带外重启 + 留用退出条件
```
脚本已自动执行 ①–⑦ 并给出建议;判读人重点复核 ⑤(因果链是否成立)、⑧(是否需要主机日志)与 ⑨(处置是否匹配现场)。

## 工作流

### 第 1 步:跑解析脚本(先拿确定性事实,别手算)
脚本封装全部逻辑:多盘发现 → 按时间排序 → 逐头聚合 → 8 类判定 → 故障分类 → 机群报告,每次结果一致。
```bash
python3 scripts/analyze_sm2.py <目录>          # 单盘或多盘(一台服务器)都可
python3 scripts/analyze_sm2.py <目录> --json   # 追加机器可读 JSON
```
> 纯标准库,无需 pandas。脚本已强制 UTF-8 输出;路径含中文/控制台 GBK 时若仍乱码,重定向到 .md 文件再读。

它直接给出:**机群汇总表(按健康度差→好排序)** + 每块盘的**逐类(8 类)分析表** + **逐磁头明细表** + 结论与处置。

### 第 2 步:对照参考做判读
脚本给结论,**`references/field_reference.md` 给依据**。需要解释"为什么这么判"、查某字段含义、
确认临界值、看 8 类↔字段映射、或遇到脚本未覆盖的形态时,**读 `references/field_reference.md`**。
核心方法:
1. **种群相对法**:同一块盘的 N 个磁头同工艺同负载,横向互比挑离群头(FAFH/iter 取高离群、amp 取低离群)。
2. **组合判读**:单项 Raw>0 故障概率约 30–40%;第1类(g_list/vis_rd_err)+第2类(不可恢复读)同时非零且增长,概率升至约 76%——最该立即换盘。
3. **`OTFErr=26728`(0x6868)是固件常量,忽略。**

### ⚠ 第 3 步:务必确认时间方向(最易错,会让结论反掉)
记录按 `poh` 排序,**`poh` 最大 = 最新**;多数导出倒序(record 0=最新)。**趋势必须按 旧→新 解读。**
否则会把"`g_list` 0→1100 增长(在恶化)"误读成"1100→0 自愈(已修复)"——真实事故报告里出现过此错误。
自检:`g_list` 与 `command_timeout` 是单调累计计数器只增不减;若解读出现"下降",基本是方向读反。
脚本已按 `poh` 升序计算,输出 `方向: grow/shrink/flat` 即旧→新。

### 第 4 步:得出健康结论与处置
按 `field_reference.md` 第 6 章判定矩阵逐盘归类(健康 / 亚健康 / 单磁头退化 / 多磁头退化 /
某类别异常 / 固件死锁),区分**活跃退化 vs 暂稳**;多盘场景按机群汇总表"差→好"给处置优先级。
处理方法见第 8 章。

### 第 5 步(可选):关联主机日志
SM2 只反映盘体内部。若需把磁头退化接到 I/O 错误/卷宕机,结合主机 `dmesg`/`messages`
(关键词 `Medium Error`、`xfs_do_force_shutdown` 等)与 `xfs_repair` 恢复流程——见第 9 章。

## 关键纪律(一句话回顾)
- **时间方向**:`poh` 大=新,按旧→新读趋势,否则结论反。
- **种群相对**:同盘磁头互比找离群头。
- **整盘 SMART 会骗人**:`g_list` 整盘级可能恒为 0,退化只在逐头可见。
- **覆盖度要诚实**:第 3/4/7 类部分覆盖,第 8 类(SSD)对 HDD 不适用——结论里标注清楚。
- **结论边界**:SM2 只证明"盘的哪个部位/磁头退化",业务影响需主机日志佐证。
